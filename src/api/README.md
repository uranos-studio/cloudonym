The Hono-based Worker API (`/v1/*`), `/llms.txt` and telemetry — the Worker entry is `src/api/index.ts`. `/openapi.json` is a static asset in `public/`.

- Every message in a response is `{ code, field?, params?, message }` (`toWireMessage` in `serialize.ts`) — sentences come from the `src/messages/` dictionary
- **Every failure response goes through the single `fail()` in `errors.ts`** (400 · 403 · 409 · 413 · 429 · 500). New failure paths use `fail()` too — `no-hangul.test` and `openapi.test` validate sample responses against the spec
- Responses carry `version` (`src/version.ts`). When a request's `rules_version` differs from the current rules revision, the answer is 409 (`schemas.ts`)
- Routes — `POST /v1/generate` (catalog: every rule of the provider · sequence `01`) · `POST /v1/names` (picked resources and counts · D39) · `POST /v1/wizard` (a whole project: project-level items and services · D66) · `POST /v1/validate` · `GET /v1/health` · `POST /v1/events` (UI beacon) · `GET /llms.txt`
- A required field that is absent is 400 `request.field_missing` (no `params`); a value outside the list is `request.value_unsupported` with the value echoed back
- `/v1/names` — `parseNamesBody` checks only the shape of provider and context and passes `resources` to core `validateSelection`. A 400 carries the core `selection.*` codes as they are (no API-only codes), and echoed `type` · `role` values are rebuilt from the original input, cut to 80 characters and written as `\uXXXX`. Each item's `scope` (placement scope) and `uniqueness` are added from the rule by `toWireNames` — the sentences describing these two fields live in `SCOPE_MEANING` · `UNIQUENESS_MEANING` in `llms.ts`, and `openapi.json` uses the same sentences
- `/v1/wizard` — `parseWizardBody` checks the shape (provider · `project` object · string lengths), turns the request names into the core wizard model (`project_picks` → `projectPicks`, `rule` → `ruleId`) and passes it to core `validatePlan`, the single wizard check. A 400 carries the core `wizard.*` and `selection.*` codes; an error about one element has `field` = `toWirePath(path)` — the core model path in request names (`projectPicks[0].instances[0].attach.data[1]` → `project_picks[0].instances[0].attach.data[1]`) — and errors about the whole plan have no `field`. Project context errors are prefixed `project.`, a service purpose error is `services[i].purpose`. `toWireWizard` adds `namespace` · `level` · `tier` · `parent` · `attach` to each item, maps labels by namespace and writes label messages with `field` `<namespace>.<label key>`. `/v1/names` is unchanged
- The conflict fixtures (two test-only rules) are not in the rule table and cannot be reached over HTTP — `names-conflict.test.ts` mocks `rulesFor` to check them. Production code has no test hooks
- **Only enabled providers are accepted** (D45) — `providers` defaults to `ENABLED_PROVIDERS`; a provider that is not enabled is 400 `request.provider_not_enabled` + `supported` on `/v1/generate`, `/v1/names`, `/v1/wizard` and `/v1/validate`
- `GET /catalog.json` (`catalog.ts` — D46) — the catalog rows and region table of the enabled providers, serialized to JSON once at module load. Same shape as `/llms.txt` (one-day cache · CORS `*` · rate limit on GET only · counter `catalog_json_accessed`). The path must be in `run_worker_first` in `wrangler.jsonc` for the Worker to receive it
- Telemetry (`telemetry.ts` — D56) — instead of the raw UA it records only the four `client_class` values from `classifyClient(ua)` (`ai_agent` · `browser` · `cli` · `other`) and `is_ai_agent`. The `ui_copy` beacon requires `target` (the six `UI_COPY_TARGETS` in `schemas.ts`); `target` on other events is dropped. The wizard's `ui_generate` beacon and `api_wizard` carry `chip_rules` and `custom_rules` (D71) — rule ids only, picked with a preset chip or with Custom; `ruleIdList` keeps the ids of the engine's rule table and drops a field that is not an array of strings or is longer than the rule count. KV counters are unchanged; the two fields go to Axiom only. The client IP is passed by `ratelimit.ts` only as the key of the rate-limit binding and is stored nowhere — the `/privacy` text (`src/messages/en.ts`) must state the same
- Release checks are not counted (`telemetry.ts` — D99) — when the `x-cloudonym-telemetry-skip` header equals the secret `TELEMETRY_SKIP_TOKEN` (`constantTimeEqual`), `logTelemetry` writes nothing to KV or Axiom. With no secret the header is ignored. Rate limiting and responses do not look at it. KV counters are approximate (D16); counts come from Axiom (one record per event; a record that fails to send is lost).

## 한국어

Hono 기반 Worker API(`/v1/*`)와 `/llms.txt`, 텔레메트리 — Worker 엔트리는 `src/api/index.ts` 다. `/openapi.json` 은 `public/` 의 정적 자산이다.

- 응답의 메시지는 전부 `{ code, field?, params?, message }`(`serialize.ts` 의 `toWireMessage`) — 문장은 `src/messages/` 사전이 만든다
- **모든 실패 응답은 `errors.ts` 의 `fail()` 하나를 지난다** (400 · 403 · 409 · 413 · 429 · 500). 새 실패 경로도 `fail()` 로 낸다 — `no-hangul.test` · `openapi.test` 가 표본 응답을 명세로 검증한다
- 응답에 `version`(`src/version.ts`)을 싣는다. 요청의 `rules_version` 이 지금 규칙 버전과 다르면 409 (`schemas.ts`)
- 라우트 — `POST /v1/generate`(카탈로그: provider 의 규칙 전부 · 순번 `01`) · `POST /v1/names`(고른 리소스와 개수 · D39) · `POST /v1/wizard`(프로젝트 한 번 — 프로젝트 공용 항목과 서비스 · D66) · `POST /v1/validate` · `GET /v1/health` · `POST /v1/events`(화면 비콘) · `GET /llms.txt`
- 반드시 있어야 할 필드가 없으면 400 `request.field_missing`(`params` 없음), 목록 밖 값이면 `request.value_unsupported` 가 그 값을 되돌려 싣는다
- `/v1/names` — `parseNamesBody` 는 provider · context 모양만 보고 `resources` 는 core `validateSelection` 에 넘긴다. 400 은 core `selection.*` 를 그대로 싣고(API 전용 코드 없음) 되돌려 싣는 `type` · `role` 값은 원래 입력에서 80자 · `\uXXXX` 로 다시 만든다. 항목의 `scope`(배치 범위) · `uniqueness` 는 `toWireNames` 가 규칙에서 붙인다 — 두 필드의 설명 문장은 `llms.ts` 의 `SCOPE_MEANING` · `UNIQUENESS_MEANING` 이 정본이고 `openapi.json` 이 같은 문장을 쓴다
- `/v1/wizard` — `parseWizardBody` 는 모양(provider · `project` 객체 · 문자열 길이)을 보고, 요청 이름을 core 마법사 모델로 바꿔(`project_picks` → `projectPicks` · `rule` → `ruleId`) 마법사 검사 하나인 core `validatePlan` 에 넘긴다. 400 은 core `wizard.*` · `selection.*` 를 싣고, 요소 하나에 걸린 오류의 `field` 는 `toWirePath(path)` — core 모델 경로를 요청 이름으로 바꾼 것(`projectPicks[0].instances[0].attach.data[1]` → `project_picks[0].instances[0].attach.data[1]`) — 이고 모델 전체 오류에는 `field` 가 없다. 프로젝트 문맥 오류는 `project.` 접두, 서비스 purpose 오류는 `services[i].purpose`. `toWireWizard` 가 항목에 `namespace` · `level` · `tier` · `parent` · `attach` 를 더하고 라벨을 이름공간 맵으로, 라벨 기록의 `field` 를 `<이름공간>.<라벨 키>` 로 싣는다. `/v1/names` 는 바뀌지 않는다
- 충돌 fixture(시험 전용 규칙 둘)는 규칙 표에 없어 HTTP 로 닿지 않는다 — `names-conflict.test.ts` 가 `rulesFor` 를 mock 해 본다. 운영 코드에 시험용 훅을 두지 않는다
- **켜진 CSP 만 받는다** (D45) — `providers` 기본값은 `ENABLED_PROVIDERS`, 꺼진 provider 는 `/v1/generate` · `/v1/names` · `/v1/wizard` · `/v1/validate` 모두 400 `request.provider_not_enabled` + `supported`
- `GET /catalog.json`(`catalog.ts` — D46) — 켜진 CSP 의 catalog 행과 지역 표를 모듈 로드 때 한 번 JSON 으로 만들어 둔다. `/llms.txt` 와 같은 꼴(하루 캐시 · CORS `*` · GET 만 요청 제한 · 카운터 `catalog_json_accessed`). `wrangler.jsonc` 의 `run_worker_first` 에 경로가 있어야 Worker 가 받는다
- 계측(`telemetry.ts` — D56) — UA 원문 대신 `classifyClient(ua)` 의 `client_class` 넷(`ai_agent` · `browser` · `cli` · `other`)과 `is_ai_agent` 만 싣는다. `ui_copy` 비콘은 `target`(`schemas.ts` 의 `UI_COPY_TARGETS` 여섯)이 필수 · 다른 이벤트의 `target` 은 버린다. 마법사의 `ui_generate` 비콘과 `api_wizard` 는 `chip_rules` · `custom_rules`(D71)를 싣는다 — 칩으로 · Custom 으로 고른 규칙 id 뿐이고, `ruleIdList` 가 엔진 규칙 표의 id 만 남기며 문자열 배열이 아니거나 규칙 수보다 긴 칸은 버린다. KV 카운터는 그대로이고 두 칸은 Axiom 에만 간다. 클라이언트 IP 는 `ratelimit.ts` 가 제한 바인딩의 키로만 넘기고 어디에도 싣지 않는다 — `/privacy` 문장(`src/messages/en.ts`)이 이 사실과 같아야 한다
- 배포 점검 요청은 세지 않는다(`telemetry.ts` — D99) — `x-cloudonym-telemetry-skip` 헤더 값이 비밀 `TELEMETRY_SKIP_TOKEN` 과 같으면(`constantTimeEqual`) `logTelemetry` 가 KV · Axiom 어디에도 쓰지 않는다. 비밀이 없으면 헤더를 무시한다. 요청 제한 · 응답은 이 헤더를 보지 않는다. KV 카운터는 근사치(D16)이고 정확한 수는 Axiom 이 기준이다.
