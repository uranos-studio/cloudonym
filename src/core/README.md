Pure logic (constraints · generation · validation) with zero runtime dependencies, imported by both the browser and the Worker.

- **It does not build sentences** — violations, steps, explanations and parse errors come back as `CoreMessage` (the discriminated union in `messages.ts`: `code` · `field` · `params`). Sentences are built in `src/messages/`
- String literals in non-test sources contain no Hangul — `no-hangul.test.ts` counts only literal nodes through the TypeScript compiler API (comments are allowed)
- A change that can alter a name, verdict, suggestion or label for the same input bumps `RULES_REVISION` (`revision.ts`) and rewrites `rules-fingerprint.json`. The fingerprint holds a token hash of this folder's non-test sources (except `revision.ts` and `baseline-inputs.ts`), so the revision must be bumped when any logic token changes, even if the output samples stay the same. Changing only comments, whitespace or `displayName` wording does not change the fingerprint
- Every rule states `scope` (where the name must be unique — a key of `SCOPES` in `scopes.ts`), `entity` (the uniqueness class — the provider's type name), `category` (display grouping) and `uniqueness` (`none` is the AWS Name tag). Scope rows carry an official `docUrl` that says "unique within this". The resource tree is built by `buildTree(provider, rules?)` in `tree.ts` from `SCOPES` and `RULES` (`rules` is passed only by the UI's test fixtures) — the tree is never written by hand. Adding a rule or a scope row grows the tree
- Sequence and role are values of an **item**, not of the context (`tokenValues(ctx, rule, { seq, role })` — without them `01` · `sync`, the same as today's output). `generateMany(ctx, provider, selection)` builds a name for every picked item — sequences have two digits (`01`…`99`); rules without input and role rules give one name. The selection first goes through `validateSelection(provider, raw, rules?)` in `selection.ts` (count 1–99 · items ≤ 200 · total names ≤ 200 · no duplicate `type` · count 1 for rules without a sequence · roles only on role rules) — the API, the UI and share links use the same function
- `conflict.ts` catches the same name in the same class (`entity`) within one request. **Every** conflicting item gets `valid:false` and `name.conflict`, and `ManyResult.conflicts` is the summary — exports look at each item's `valid`, so a conflicting name never leaves as valid. One request is treated as one instance of the parent scope (one RG · one project · one VPC). Test-only conflict rules live in `__fixtures__/conflict.ts`
- **The enabled providers are `ENABLED_PROVIDERS` in `types.ts` (`['gcp']` in this release)** (D45). `Provider` and `PROVIDERS` keep all three, and rules, tests and baselines run over all three providers — only what is exposed follows this array
- **For Google Cloud, the catalog overrides abbreviations, `entity`, the region-token kind (`none` · `region` · `zone`) and the kind table** (D46 · D47). The source is `catalog/*.json` at the repository root; `npm run catalog` writes the generated files `rules/gcp-catalog.ts` and `regions-data.ts` (never edit them by hand), and `applyCatalog(rule)` in `rules/gcp.ts` overrides each rule. Lookups live in `catalog.ts` (`catalogFor` · `rowOf` · `allowedKinds` · `kindToken`)
- **Regions are provider-specific codes** (D49 · D50) — `canonicalRegion(raw, provider)` in `regions.ts` resolves a region or zone name, a code or `global` into `{ region, zone? }`. `parseContext(raw, provider)` takes the provider. A zonal rule without a zone gives `name.zone_required` (empty name), and a missing required kind gives `name.kind_required` (the name is kept) — on both the `generate` and `generateMany` paths

## 한국어

순수 로직(제약 · 생성 · 검증) — 런타임 의존성 0, 브라우저와 Worker 양쪽에서 import 한다.

- **문장을 만들지 않는다** — 위반 · 단계 · 설명 · 파싱 오류는 `CoreMessage`(`messages.ts` 의 판별 유니언: `code` · `field` · `params`)로 돌려준다. 문장은 `src/messages/` 가 만든다
- 비시험 소스의 문자열 리터럴에 한글이 없다 — `no-hangul.test.ts` 가 TypeScript 컴파일러 API 로 리터럴 노드만 센다(주석은 된다)
- 같은 입력에서 이름 · 판정 · 제안 · 라벨이 바뀔 수 있는 변경은 `RULES_REVISION`(`revision.ts`)을 올리고 `rules-fingerprint.json` 을 다시 쓴다. 지문에는 이 폴더 비시험 소스(`revision.ts` · `baseline-inputs.ts` 제외)의 토큰 해시가 들어 있어, 출력 표본이 같아도 로직 토큰이 하나라도 바뀌면 올려야 한다. 주석 · 공백 · `displayName` 문구만 바꾼 것은 지문을 바꾸지 않는다
- 규칙마다 `scope`(이름이 유일한 범위 — `scopes.ts` 의 `SCOPES` 키) · `entity`(고유성 부류 — CSP 유형 이름) · `category`(표시 분류) · `uniqueness`(`none` 은 AWS Name 태그)를 적는다. 범위 행에는 「이 안에서 유일하다」는 공식 문서 `docUrl` 이 붙는다. 리소스 트리는 `tree.ts` 의 `buildTree(provider, rules?)` 가 `SCOPES` 와 `RULES` 에서 만든다(`rules` 는 화면의 시험 전용 fixture 가 넘긴다) — 트리를 손으로 적지 않는다. 규칙 · 범위는 행을 더하면 트리가 따라 는다
- 순번 · 역할은 문맥이 아니라 **항목**의 값이다(`tokenValues(ctx, rule, { seq, role })` — 없으면 `01` · `sync`, 지금 출력과 같다). `generateMany(ctx, provider, selection)` 이 고른 항목마다 이름을 만든다 — 순번은 두 자리(`01`…`99`), 입력 없는 · 역할 규칙은 하나. 선택은 먼저 `selection.ts` 의 `validateSelection(provider, raw, rules?)` 를 거친다(개수 1~99 · 항목 ≤ 200 · 이름 Σ ≤ 200 · `type` 중복 금지 · 순번 없는 규칙에 개수 1 · 역할은 역할 규칙에만) — API · 화면 · 공유 링크가 같은 함수를 쓴다
- 같은 요청 안에서 같은 부류(`entity`)의 같은 이름은 `conflict.ts` 가 잡는다. 충돌한 **항목마다** `valid:false` 와 `name.conflict` 가 붙고 `ManyResult.conflicts` 는 그 요약이다 — 내보내기가 항목의 `valid` 를 보므로 충돌한 이름이 유효로 나가지 않는다. 한 요청은 부모 범위의 한 인스턴스(한 RG · 한 프로젝트 · 한 VPC)로 본다. 시험 전용 충돌 규칙은 `__fixtures__/conflict.ts`
- **켜진 CSP 는 `types.ts` 의 `ENABLED_PROVIDERS`(이번 릴리스는 `['gcp']`)다** (D45). `Provider` · `PROVIDERS` 는 셋 그대로이고 규칙 · 시험 · 기준선은 세 CSP 를 다 돈다 — 노출만 이 배열을 따른다
- **GCP 의 약어 · `entity` · 지역 토큰 종류(`none` · `region` · `zone`) · 종류 표는 catalog 가 덮는다** (D46 · D47). 정본은 저장소 뿌리의 `catalog/*.json`, `npm run catalog` 가 생성 파일 `rules/gcp-catalog.ts` · `regions-data.ts` 를 쓰고(손으로 고치지 않는다), `rules/gcp.ts` 의 `applyCatalog(rule)` 가 규칙마다 덮는다. 조회 함수는 `catalog.ts`(`catalogFor` · `rowOf` · `allowedKinds` · `kindToken`)
- **지역은 CSP 별 코드다** (D49 · D50) — `regions.ts` 의 `canonicalRegion(raw, provider)` 가 리전 · 존 이름 · 코드 · `global` 을 `{ region, zone? }` 로 푼다. `parseContext(raw, provider)` 는 provider 를 받는다. 존 규칙에 존이 없으면 `name.zone_required`(이름 빈 값), 필수 종류가 없으면 `name.kind_required`(이름은 둔다) — `generate` · `generateMany` 두 경로 모두
