# Design decisions

This is the public record of Cloudonym's design decisions. Code comments and the README refer to them by number (`D1`–`D29`, then `D30'`, `D31` and `D37`–`D43` for the four-step screen and `POST /v1/names`, `D45`–`D58` for the 0.1.0 release, `D59`–`D76` for the naming wizard, `D77`–`D79` for region tokens, `D80` for evidence kinds, and `D81`–`D105` for the wizard, API, plan file, CLI and header changes that followed, up to the 0.1.2 release and after). Later decisions — mostly corrections made after checking a rule against the official provider documentation — are listed by date below the numbered table.

The engine has one fatal bug class: **reporting an invalid name as valid**. Where a document is ambiguous, the decision always goes the conservative way — the engine may reject a name the provider would accept, but it must not accept a name the provider would reject.

The per-rule comparison against official documentation is in [docs/rule-verification.md](rule-verification.md).

## Numbered decisions (D1–D29)

Each row records one design choice and the reason for it. Numbers that are not listed (D5, D6, D22, D32–D36, D44) are not used in this record.

| # | Topic | Decision | Why |
|---|---|---|---|
| D1 | API paths | **`POST /v1/generate`** and **`POST /v1/validate`**. No GET query variant, no `/v2/bulk-generate`. | Bulk use is covered by `providers[]` — one request returns all three providers. |
| D2 | Test IDs | Keep the five original IDs (`TC-GCP-01`, `TC-AZ-01`, `TC-AWS-01`, `TC-COM-01`, `TC-COM-02`). New scenarios get new numbers: tag key/value limits → `TC-AWS-02`; Windows node pool → `TC-AZ-02`. A 222-character dotted GCS bucket (`TC-GCP-02`) is out of scope. | One ID, one meaning. |
| D3 | Component file extension | **`.tsx`** | Strict TypeScript and `.jsx` do not mix. |
| D4 | Hosting | **A single Cloudflare Worker with Workers Static Assets** (`@cloudflare/vite-plugin`), not Pages + Workers. | Cloudflare's current recommendation; one deploy target keeps CI simple. |
| D7 | Telemetry | **Axiom only.** No PostHog. | A third-party analytics script conflicts with the "no sign-up, instant" promise. Revisit after launch if needed. |
| D8 | Number of providers | **Three** (AWS, Google Cloud, Microsoft Azure) — in the `Provider` union and the OpenAPI enum. | No source gave OCI naming limits; the table is not filled with numbers nobody documented. |
| D9 | Rule definitions | A **typed `const` object in `src/core/constraints.ts`**. No JSON/YAML rule files, no documentation-scraping script. | Type-checked, no runtime parsing, still declarative. The rules and formula sections of `/llms.txt` are generated from the same object so they cannot drift. |
| D10 | Shortening | **Three-step shortening**: (1) drop the tokens in `rule.optional` one at a time, in the listed order (least important first — e.g. `['region','owner']` for a GCP service account); (2) shorten the remaining variable tokens via the abbreviation dictionary, then an even length budget; (3) if it still does not fit, return `valid: false`. Never silently truncate. | Combines "drop owner/region when too long" with a budget-based approach, in that order. |
| D11 | Unique seed (`L_unique`) | **`L_unique = 0`**; the budget formula keeps a slot for it. | No unique seed is generated; the slot lets one be added without changing the formula. |
| D12 | Names | Repository **`cloudonym`**, product name **Cloudonym**. The domain is undecided, so no domain is hard-coded — API paths are relative (`/v1/...`). | "CName" collides with DNS CNAME. |
| D13 | Protected tokens and minimum length | Protected tokens: **`slug`, `seq`, `role`, `env`** (`env` is a three-letter code; shortening it loses meaning). After shortening, every variable token must be **at least 2 characters** — otherwise shortening gives up and returns a failure. The abbreviation dictionary has no one-letter values. Invariant of `fit`: no `--`, no leading/trailing separator, no empty variable token. | `env` loses its meaning when shortened, and a one-letter token makes a name unreadable; a failure is better than a malformed name. |
| D14 | Two meanings of "allowed characters" | Split them. `allowed` = the character set **we generate with** (house style; used for normalisation). `pattern`, `forbidden` and length = the **provider's physical rule** (used for validation). `/v1/validate` checks only physical rules — S3 `example.com` and GCS `my_bucket` are valid because the providers accept them. `noConsecutiveSeparator` is set only where the provider forbids it (Key Vault, RDS). `NameResult.rule` carries both. | Validating against the generation style would reject names the provider accepts. |
| D15 | Wire field naming | **snake_case on the wire** (`is_truncated`, `is_transformed`, `metadata.generated_labels`); camelCase in the core, converted by `src/api/serialize.ts`. `is_transformed` is true when normalisation changed characters or when hyphens were dropped because the rule allows no separator. `metadata` splits `generated_labels`, `label_violations` and `label_transformed` **per provider**. The providers in the response equal the requested `providers`. Non-array `providers` → 400; empty array → 400; omitted → all three. | — |
| D16 | KV counter accuracy | **Approximate by design.** Daily counters use read-modify-write, so concurrent requests can lose a count, and writes over the per-key rate limit are dropped (errors are swallowed inside `waitUntil`). Exact numbers come from Axiom events. | A usage counter does not need to be exact; Axiom holds the exact events. *Revised by D99: Axiom is the source for counts and KV is an approximate one-year trend; release-check requests are not counted.* |
| D17 | Instrumentation paths | `/llms.txt` is **served by the Worker** (listed in `run_worker_first`) so the counter and `Cache-Control` live in code. **The UI calls the engine directly in the browser** and sends two beacons to `POST /v1/events`: `ui_visit` (once per page load, de-duplicated per tab via `sessionStorage`) and `ui_generate` (debounced 1 s). No naming context is sent. "Visits" = daily sum of `ui_visit`; unique visitors are not counted (no identifiers). | Counting and caching belong in code; calling the engine in the browser avoids an API round trip, and the beacons carry no naming context. |
| D18 | Rule coverage | All **six resource classes** (VM, VPC, subnet, database, storage bucket, identity) for all three providers — Azure identity is a **user-assigned managed identity**; Key Vault is an extra storage-class rule. 24 rules. Each value was checked against official documentation; a rule without a documented source is dropped. | No number is used without a documented source. |
| D19 | Known lists only | `forbidden` holds **only strings the official documents state explicitly** (e.g. `google`, `g00gle`). Other look-alike spellings and trademarks are not checked; `/llms.txt` and the README say the engine does not replace the provider's final decision. | Reserved-word rules in the documents are open-ended. |
| D20 | Limits spanning several fields | **Conservative.** Cloud SQL instance ID max **67** (98 for `project-id:instance-id` − 30 longest project ID − 1). Azure VM follows the **host name rule**, with a narrow pattern (alphanumerics, dot, hyphen). AWS Name tag measured with `.length` (UTF-16), 1–256, empty rejected. Results mark such limits as conservative in a `note` next to `docUrl`. | Rejecting a valid name can be worked around; accepting an invalid one is the fatal bug class. |
| D21 | Label value characters | GCP label conversion: **lowercase + remove characters outside `[\p{L}\p{N}_-]`** (with the `u` flag — `\p{L}`, not `\p{Ll}`, because Hangul is `Lo`). Korean values survive. Keys are our fixed five and are not checked. | GCP label values allow international characters; the lowercase-start rule applies only to keys. |
| D23 | Message structure | The engine returns **message codes, not sentences**: each violation, step, label change and context error is `{ code, field?, params? }`, a discriminated union per code (`src/core/messages.ts`; API-only codes in `src/api/codes.ts`). Required `params` are typed per code. Sentences are made by the presentation layer `src/messages/` — the core never imports it. User values in `params` (`from`, `to`, `value`) are display strings; API values are shown via the same 80-character description as before. When several `providers` are invalid there is one message per value (`field: "providers[i]"`). | Sentences inside the engine would force an engine change for every new language, and the UI used to find fields by string prefix. Typed params make a missing parameter a compile error. |
| D24 | Catalog format | The catalog is **TypeScript** (`src/messages/en.ts`): `messages` (one function per code) and `ui` (screen text). **English only**; no language switch and no `Accept-Language`. Another language is one more file filling the same `Catalog` type. The three AWS display names are English data (`VPC (Name tag)` …), not catalog entries. | A mapped type turns a missing code or parameter into a `tsc` error; JSON would need runtime parsing and its own template rules. A switch with one language does nothing. |
| D25 | Wire format (breaking, before release) | `violations`, `steps`, `errors`, `label_violations[p]`, `label_transformed[p]`, `transformed` and `rule.notes` are arrays of **`{ code, field?, params?, message }`**. `reason` is removed (use `steps`); `rule.note` becomes `rule.notes` (always an array). Responses of generate, validate and health carry **`version: { engine, rules }`**. **Every failure** (400, 403, 409, 413, 429, 500) goes through one function and has the shape `{ success: false, errors: [...], supported? }`. The OpenAPI document covers `/health` and 500. | `message` keeps `jq '.violations[].message'` readable. Keeping `reason` next to `steps` would let the two drift. With six separate error paths, one would sooner or later ship without `message`. |
| D26 | Versions | `version.engine` = `package.json` `version` (now **0.1.2**; `src/version.ts` holds the value and a test pins it to `package.json`, so the whole manifest is not bundled). `version.rules` = `RULES_REVISION` in `src/core/revision.ts`, format **`YYYY-MM-DD.N`**, bumped for any change that can give a different name, verdict, suggestion or label for the same input. `src/core/rules-fingerprint.json` stores a sha256 over the rule data and the outputs of a fixed input matrix; a test recomputes it and CI compares it with `main` (fingerprint changed without a new revision, or the reverse, fails). Exports carry the versions: the Terraform locals start with a two-line comment, the tags JSON copy is `{ "version": {…}, "labels": {…} }`, and the share-link hash has a `v` key. | A date alone cannot tell two changes on one day apart, and updating only the fingerprint is caught by comparing with `main`. |
| D27 | Name stability | **The caller pins; the API does not reproduce old rules revisions — it reports the mismatch.** (1) Optional request field `rules_version`: if it differs from the current revision the API answers **409** `request.rules_version_mismatch { requested, current }`; a non-string is 400. (2) The UI share link stores `v`. State read from a link is kept apart from the form: while the form equals the linked state the app does not rewrite the hash (a reload keeps the old `v` and the notice); editing the form drops the link state and the hash gets the current `v`. **Share URL** always uses the current revision. (3) The Terraform example has a `rules_version` variable, `ignore_changes = [name]` on the existing VM `lifecycle`, outputs the real resource name separately from the API candidate, and a pinned mode that skips the API call. Old revisions are not served. | `data "http"` runs on every plan, so a rule change would propose replacing a VM. Serving old revisions would need copies of the rule table. A pinned caller blocked by 409 needs a way out — the pinned mode. |
| D28 | Meaning of PASS | One sentence in four places (UI, `/llms.txt`, OpenAPI `valid`, README): *PASS / `valid: true` means the name satisfies the documented naming checks of this rules revision (length, pattern, reserved words). It does not mean the name is available or that you may create it — uniqueness, permissions, quotas and organisation policy are not checked. Generated names are not guaranteed unique: shortening can map two different contexts to the same name.* The source is `ui.pass_meaning` in `src/messages/en.ts`; tests check the static copies. | Reading PASS as "you can create this" hides the limits in D19 and D20. |
| D29 | Log messages | Log output (`console.error`) is **out of scope** for the message codes. | Logs are not shown to users or agents. |

## Four-step screen and `POST /v1/names` (D30', D31, D37–D43)

The screen that listed every resource of all three providers was replaced by four steps — **① Cloud** (pick one provider) **② Context** (the five values) **③ Resources** (a tree built from each provider's documented uniqueness scopes, with a check box and a count per resource) **④ Names** (only the picked resources, with PASS/FAIL and copy). The API gained `POST /v1/names` for the same per-resource selection.

D30 was reused with a changed meaning — hence **D30'**. D32–D36 are not used. New decisions start at D37.

| # | Topic | Decision | Why |
|---|---|---|---|
| D30' | Sequence number and role | `seq` and `role` are values of a **selected item** (`resources[i]` of `/v1/names`), not of the naming context. `seq` is made from `count` (`01`…`99`); `role` matches `^[a-z0-9]{2,16}$`. `/v1/generate` does not take either. Without them the defaults are `01` and `sync`, and every name is **character-for-character the same** as when both were fixed. | Counts differ per resource (two VMs, two NICs). In the context, every resource in one request would get the same sequence number. |
| D31 | Uniqueness class `entity` | Every rule carries `entity`, the provider's own type name for uniqueness: Azure's *Entity* column, the GCP discovery resource name (e.g. `compute.instances`), the AWS API type name. Rules that share a type (Linux/Windows VM, Linux/Windows AKS node pool) carry the same value. | `resource_type` is Cloudonym's slug, not the unit in which the provider enforces unique names. |
| D37 | Scope model | `ResourceRule.scope` is a key of `SCOPES` (`src/core/scopes.ts`), e.g. `azure:resource_group`. Each scope row has an id, provider, display name, optional parent and a `docUrl`. The resource tree is **derived** from `SCOPES` plus the rule table by `buildTree(provider)`; there is no hand-written tree file. | A separate tree file would drift from the rule table (the same reason `/llms.txt` is generated, D9). Each scope needs a source URL to be "the provider's documented uniqueness scope". |
| D38 | Place of AWS `Name` tags | `uniqueness: 'none'` — the provider enforces no uniqueness on tag values. In the tree they sit by **containment** (a subnet under its VPC), and their `docUrl` is the tagging page ("Tags don't have any semantic meaning"). | Tag names have no uniqueness scope; Cloudonym does not invent one. |
| D39 | `POST /v1/names`; `/v1/generate` stays | Body `{ provider, context, resources: [{ type, count?, role? }], rules_version? }`. The response has the same frame as `/v1/generate` (`data[provider]`, provider-keyed `metadata`) with `items[]`, `conflicts[]` and `valid`. `/v1/generate` is unchanged. | `data[provider][type]` cannot hold two names of one type, so extending `/v1/generate` would break its callers. |
| D40 | Count and request limits — **one validator** | `count` 1–**99** (default 1), sequence numbers are **always two digits**, at most **200** items and **200** names (Σ count) per request, no duplicate `type`, `count > 1` only on rules with a sequence number, `role` only on rules with a role. All of this is `validateSelection(provider, raw)` in `src/core/selection.ts`; the API (400 `selection.*`), the screen (stepper, link restore) and the URL-hash decoder call the same function. | With three digits the 15-character Windows VM name no longer fits (`name.cannot_fit`); with two digits, `count: 1` gives exactly the old output. The screen calls the engine directly (D17), so a check that lived only in the API could be bypassed by the screen or a link. 200 bounds what one screen and one share link can carry, not the response size. |
| D41 | Same-class conflicts are **item** failures | Key `provider · entity · comparison name` (Azure lower-cased; AWS lower-cased conservatively; GCP as is). Two equal names conflict even with `uniqueness: 'none'`. **Each conflicting item** gets `valid: false` and a `name.conflict` violation; `conflicts[]` is a summary. One request is treated as one instance of the parent scope (one resource group, one project, one VPC). | Every export (copy all, names JSON, Terraform `# INVALID:`) and every card reads the item's `valid`. If only the overall `valid` were false, a conflicting name would be exported as valid. |
| D42 | Share-link hash v2 | Keys `p` (provider) and `r` (`{ type: value }` — **one value per item**: a number for count rules, a role string for role rules, `1` for rules with no input). Old five-key links still open (step ① asks for the provider). Unknown types, wrong value kinds and out-of-limit items are **dropped with a one-line notice**. The hash length limit is a **fixed formula** — ≤ 200 items, `resource_type` ≤ 40 characters, role ≤ 16 characters (tests measure all three). | If one type could appear under two keys the limit formula would be wrong. If the limit grew with the number of rules, a link that opened yesterday could stop opening after rules were added. |
| D43 | Bringing in rules — **conversion and detection, not synchronisation** | Development-time generators turn an official source into candidate rows; people read each row, write or confirm its `pattern`, and commit it. Changes in a source are only **detected** (`docs/rule-sources.lock.json` and `scripts/rules/check-sources.mjs`), never applied automatically. Rule tables remain typed `const` data with no runtime parsing, so **D9 still holds**. Rule files may live in a sub-folder only because the boundary and revision tests read `src/core/` recursively. | D9 rules out scraping documentation into rules at run time. Turning a sentence into a regular expression is a judgement a person has to make. |

## Release 0.1.0 — Google Cloud first (D45–D58)

The first public release opens Google Cloud only. The AWS and Azure rule data stays in the engine and in the tests; only what is exposed is switched off. The same release replaces the naming scheme: the environment value `prod`, provider region codes instead of five country values, an optional kind token, and abbreviations that come from a source-backed catalog. Names change because of this; the release is made before any public name depends on the old scheme.

| # | Topic | Decision | Why |
|---|---|---|---|
| D45 | Enabled providers (adds to D8) | `ENABLED_PROVIDERS = ['gcp']` in `src/core/types.ts`. The `Provider` union and `PROVIDERS` keep all three. The screen draws all three buttons but disables the two that are off ("Coming soon") and selects the only enabled one automatically; the API defaults to the enabled providers and answers a request for a disabled one with 400 `request.provider_not_enabled`; `/llms.txt`, the `openapi.json` `provider` enum (checked by a test) and the README follow the same list. | Shrinking the union would delete the AWS and Azure data and tests. The data stays; only exposure is switched off. A disabled button announces what is coming instead of doing nothing. |
| D46 | Catalog as the source | `catalog/gcp.json` (one row per screen row), `catalog/regions.json` (regions and zones of the three providers) and `catalog/schema.json` (JSON Schema) are the source. A development-time generator writes typed constants (`src/core/rules/gcp-catalog.ts`, `src/core/regions-data.ts`, marked as generated). A test checks that the JSON matches the schema, that the generated files equal a fresh run, and that catalog rule ids and the rule table cover each other. `GET /catalog.json` is a Worker route that serves the enabled providers only, with `version: { engine, rules }`. | Keeps D9 (typed constants, no runtime parsing) and the core import boundary while giving one JSON file as the source — the same shape as the imported Azure table (D43). A static copy would be a third place to drift. |
| D47 | Catalog overrides the rules · conflicts on both paths | The catalog sets each Google Cloud rule's abbreviation, `entity`, region-token kind (`none`, `region`, `zone`) and allowed kinds. `none` removes `region` from the template and from `optional` together. Cloud Functions 1st and 2nd gen share the entity `cloudfunctions.functions` (one name space per region and project — the single exception to D31's discovery-name rule). The same-class conflict check runs in `generate` as well as in `generateMany`. A collision test checks abbreviations, kind tokens, region and zone codes and environment values against each other, and is itself tested with a fixture it must catch. | A single source for abbreviations; a conflict is a conflict on every path. |
| D48 | Environment `prod` | `Env = 'prod' \| 'stg' \| 'dev' \| 'sbx'`; `prd`, `production`, `real` and `live` are aliases of `prod`. Every provider's names change, because `env` is protected in every template. | `prod` is the far more common spelling in public Terraform code. |
| D49 | Region codes per provider | Codes come from `catalog/regions.json`: Google Cloud by its own pattern (`asia-northeast3` → `ane3`), AWS by the AZ ID prefix (`apne2`), Azure by its geo code. `parseContext(raw, provider)` accepts that provider's region names, zone names, region codes, zone codes and `global`, and returns `{ region, zone? }`. The old country values (`kr`, `us`, `jp`, `eu`) and other providers' region names are rejected, with the matching region names in `supported`. Global resources carry no region token, and the input `global` leaves the region slot empty for every resource — the engine before 0.1.0 wrote the word `global` into the name instead. Region codes are up to five characters. | Five country values gave `us-east1` and `us-west1` the same name. |
| D50 | Zones through the region field | *Superseded by D50 (revised): names carry no zone.* No sixth context value. The `region` field also takes a zone (`asia-northeast3-a`); the share link, the form and the wire carry the text the user entered, so a zone survives a reload. Zonal rules put the zone code (`ane3a`, up to six characters) in the region slot. Without a zone, a zonal item is `valid: false` with `name.zone_required` on both generation paths; the screen keeps a picked zonal row and shows why. | Zonal resources are unique per zone; a region code alone cannot tell two zones apart. |
| D51 | `region` is protected | `region` joins the protected tokens, so shortening never cuts a region code. *Withdrawn by D50 (revised):* zonal rules also drop `region` from `optional`, because the first shortening step removes optional tokens before protection applies. Equal text from two different entities is not reported as a conflict. | Two VMs in different zones must not end up with the same name after shortening. |
| D52 | Kind token | A `kind` token sits right after the abbreviation (`…-{slug}-{kind}-{seq}`). Allowed kinds and the default are per rule (per scope). The token is left out when the value is the provider default or one of the row's grouped values; otherwise the row's token is used. The input is the value name (`POSTGRES`), not the token. Only resource policies require a kind (`name.kind_required` on both paths); the request validator rejects unsupported, unknown and missing kinds. One kind per row; tokens are at most five characters. Allowed kinds per scope follow the official network endpoint group scope table: zonal NEGs do not take `SERVERLESS`, `PRIVATE_SERVICE_CONNECT` or `GCE_VM_IP_PORTMAP`, regional NEGs do not take `GCE_VM_IP`, `GCE_VM_IP_PORT` or `NON_GCP_PRIVATE_IP_PORT`; `GCE_VM_IP_DEDICATED_BACKEND` appears only in the Terraform zonal schema and is marked as such. | Default names stay unchanged when a kind is later added. Where a schema and the official scope table differ, the official table wins. |
| D53 | Merged rows and scope choice | A screen row is a catalog row. A row that covers several rules (for example a regional and a global address) is placed at the lowest common scope and asks for the scope; the chosen scope maps to one rule. The API is unchanged — `resources[].type` is still a rule's `resourceType`. In the share link a row holds one key; extra keys of the same row are dropped and counted. A row cannot be checked before its scope is chosen. | Changing `type` would break the API contract, the OpenAPI document and the examples. No hidden default scope. |
| D54 | Descriptions live in the catalog | The one-line description, where the name is entered (gcloud, Terraform, API only), badges (`api-only`, `preview`), search aliases and the abbreviation's basis (principle, usage count, official source URL) are catalog data in English, not dictionary entries. | They are properties of a resource, not system messages; a second language would otherwise copy the catalog into the dictionary. |
| D55 | Share-link hash v3 (changes D42) | `region` holds the entered region or zone code. An `r` value is `n` or `"n:VALUE"` for count rules, a role string for role rules, `1` or `"1:VALUE"` otherwise; the length limit stays a fixed formula (longest kind value, longest region code, four-character `env`). Old `kr` links do not open. A link for a disabled provider keeps the three free fields and `env`, replaces the region with the example region, drops the selection, switches to the enabled provider and says so in one line. | Keeps "one value per item, fixed formula" while carrying kinds and zones. |
| D56 | Telemetry fields | New beacon `ui_copy` with a `target` from a fixed list of six (`share-url`, `name`, `all-names`, `names-json`, `terraform`, `tags-json`), sent only when a copy succeeds; the item key and resource type are not sent. `POST /v1/events` rejects a missing or unknown `target` on `ui_copy` with 400 and ignores `target` on other events. The raw User-Agent is no longer stored; a `client_class` (`ai_agent` by the AI-agent pattern first, `browser` for `Mozilla/…`, `cli` for curl, wget, python-requests, Go-http-client and node, otherwise `other`) and `is_ai_agent` are. An Axiom record holds `_time` (KST offset), `kst_day`, `event`, `client_class`, `is_ai_agent` and only the extra fields listed for that event; other keys are dropped. Names, the five context values, the URL hash, cookies and identifiers are not collected — tests check the whole payload text, the KV writes and the console logs (including an Axiom rejection that echoes the body), not only the keys. The client IP is read only to key Cloudflare's rate-limit binding (60-second window) and is not stored in telemetry, KV or Axiom. KV day counters expire 366 days after their last write. `/privacy` states the Axiom retention configured on the dataset; until it is set, the page names no number. | A User-Agent can carry arbitrary text; an allow-list of keys does not stop values. The privacy text must match what the code does. |
| D57 | `/docs/naming` and `/privacy` | Single-page-app paths (`not_found_handling: single-page-application`); `main.tsx` picks the page by `location.pathname`, no router dependency. The naming guide is rendered from a pure model built from the generated catalog, region table, dictionary and version — no hand-written numbers or tables. | Static HTML generation would need more work on the style policy and asset routing; the SPA path is already in use. |
| D58 | Changelog and version | `CHANGELOG.md` in Keep a Changelog form, one `## [0.1.0]` entry with a short history paragraph and the rules revision of the release (`2026-10-07.11`); `version.test.ts` checks that the entry for the engine version exists and names the current rules revision. The version stays `0.1.0` and the release is tagged `v0.1.0`; further features are planned for a later release. | One release entry for the first public version. |

## Naming wizard (D59–D76) · region tokens (D77–D79) · evidence kinds (D80) · later wizard, API and screen decisions (D81–D105)

The next stage adds a **naming wizard**: project values once, then several services inside the project, each with a purpose (`web`, `was`, `db`, file server, object storage and so on) mapped to a Google Cloud service, a minimum quantity (serverless or high availability), and the disks and IP addresses attached to each server, whose names continue the server's name. The existing four-step screen stays for picking any catalog row. These decisions were made before the code and are now implemented in the engine, `POST /v1/wizard`, the screen at `/` and `/pick`, `/llms.txt`, `/openapi.json` and `/docs/naming`; each row names what it changes. Before any engine change, the outputs of the time were frozen as a compatibility oracle (D70).

| # | Topic | Decision | Why |
|---|---|---|---|
| D50 (revised) | No zone in names | The 14 rules whose region token is `zone` (`compute_instance`, `disk`, `autoscaler`, `future_reservation`, `instance_group_manager`, `instance_group`, `instant_snapshot_group`, `instant_snapshot`, `reservation`, `storage_pool`, `target_instance`, `zone_vm_extension_policy`, `node_group`, `network_endpoint_group`) put the **region code** in the region slot (`billing-shop-prod-ane3-gce-web-01`). `name.zone_required` is removed.
