# Design decisions

This is the public record of Cloudonym's design decisions. Code comments and the README refer to them by number (`D1`–`D29`). Later decisions — mostly corrections made after checking a rule against the official provider documentation — are listed by date below the numbered table.

The engine has one fatal bug class: **reporting an invalid name as valid**. Where a document is ambiguous, the decision always goes the conservative way — the engine may reject a name the provider would accept, but it must not accept a name the provider would reject.

The per-rule comparison against official documentation is in [docs/규칙-대조-20260928.md](규칙-대조-20260928.md).

## Numbered decisions (D1–D29)

The source material for the project (an original product brief plus several secondary research notes) disagreed in places. Each row records how the disagreement was resolved; the original brief wins unless stated otherwise.

| # | Topic | Decision | Why |
|---|---|---|---|
| D1 | API paths | **`POST /v1/generate`** and **`POST /v1/validate`**. No GET query variant, no `/v2/bulk-generate`. | Matches the original brief's code and OpenAPI document. Bulk use is covered by `providers[]` — one request returns all three providers. |
| D2 | Test IDs | Keep the five original IDs (`TC-GCP-01`, `TC-AZ-01`, `TC-AWS-01`, `TC-COM-01`, `TC-COM-02`). New scenarios get new numbers: tag key/value limits → `TC-AWS-02`; Windows node pool → `TC-AZ-02`. A 222-character dotted GCS bucket (`TC-GCP-02`) is out of scope. | One ID, one meaning. |
| D3 | Component file extension | **`.tsx`** | Strict TypeScript and `.jsx` do not mix. |
| D4 | Hosting | **A single Cloudflare Worker with Workers Static Assets** (`@cloudflare/vite-plugin`), not Pages + Workers. | Cloudflare's current recommendation; one deploy target keeps CI simple. |
| D5 | Terraform integration | Development stages 1–5 ship only a **`data "http"` example** ([examples/terraform](../examples/terraform)). A dedicated Terraform provider is growth stage 2. | The brief scoped only the example for the initial release. |
| D6 | The word "Phase" | Development order is **"development stage N"** (1–5); product roadmap is **"growth stage N"** (1–3). "Phase" alone is not used. | The word had two meanings. |
| D7 | Telemetry | **Axiom only.** No PostHog. | A third-party analytics script conflicts with the "no sign-up, instant" promise. Revisit after launch if needed. |
| D8 | Number of providers | **Three** (AWS, Google Cloud, Microsoft Azure) — in the `Provider` union and the OpenAPI enum. | No source gave OCI naming limits; the table is not filled with numbers nobody documented. |
| D9 | Rule definitions | A **typed `const` object in `src/core/constraints.ts`**. No JSON/YAML rule files, no documentation-scraping script. | Type-checked, no runtime parsing, still declarative. The rules and formula sections of `/llms.txt` are generated from the same object so they cannot drift. |
| D10 | Shortening | **Three-step shortening**: (1) drop the tokens in `rule.optional` one at a time, in the listed order (least important first — e.g. `['region','owner']` for a GCP service account); (2) shorten the remaining variable tokens via the abbreviation dictionary, then an even length budget; (3) if it still does not fit, return `valid: false`. Never silently truncate. | Combines "drop owner/region when too long" with a budget-based approach, in that order. |
| D11 | Unique seed (`L_unique`) | **`L_unique = 0`** for now; the budget formula keeps a slot for it. Seeding is growth stage 2. | Not required by the original brief; the slot lets it be switched on later. |
| D12 | Names | Repository **`cloudonym`**, product name **Cloudonym**. The domain is undecided, so no domain is hard-coded — API paths are relative (`/v1/...`). | "CName" collides with DNS CNAME. |
| D13 | Protected tokens and minimum length | Protected tokens: **`slug`, `seq`, `role`, `env`** (`env` is a three-letter code; shortening it loses meaning). After shortening, every variable token must be **at least 2 characters** — otherwise shortening gives up and returns a failure. The abbreviation dictionary has no one-letter values. Invariant of `fit`: no `--`, no leading/trailing separator, no empty variable token. | Review findings. |
| D14 | Two meanings of "allowed characters" | Split them. `allowed` = the character set **we generate with** (house style; used for normalisation). `pattern`, `forbidden` and length = the **provider's physical rule** (used for validation). `/v1/validate` checks only physical rules — S3 `example.com` and GCS `my_bucket` are valid because the providers accept them. `noConsecutiveSeparator` is set only where the provider forbids it (Key Vault, RDS). `NameResult.rule` carries both. | Review findings. |
| D15 | Wire field naming | **snake_case on the wire** (`is_truncated`, `is_transformed`, `metadata.generated_labels`); camelCase in the core, converted by `src/api/serialize.ts`. `is_transformed` is true when normalisation changed characters or when hyphens were dropped because the rule allows no separator. `metadata` splits `generated_labels`, `label_violations` and `label_transformed` **per provider**. The providers in the response equal the requested `providers`. Non-array `providers` → 400; empty array → 400; omitted → all three. | Matches the original brief's response example. |
| D16 | KV counter accuracy | **Approximate by design.** Daily counters use read-modify-write, so concurrent requests can lose a count, and writes over the per-key rate limit are dropped (errors are swallowed inside `waitUntil`). Exact numbers come from Axiom events. | Review finding. |
| D17 | Instrumentation paths | `/llms.txt` is **served by the Worker** (listed in `run_worker_first`) so the counter and `Cache-Control` live in code. **The UI calls the engine directly in the browser** and sends two beacons to `POST /v1/events`: `ui_visit` (once per page load, de-duplicated per tab via `sessionStorage`) and `ui_generate` (debounced 1 s). No naming context is sent. "Visits" = daily sum of `ui_visit`; unique visitors are not counted (no identifiers). | Review findings. |
| D18 | Rule coverage | All **six resource classes** (VM, VPC, subnet, database, storage bucket, identity) for all three providers — Azure identity is a **user-assigned managed identity**; Key Vault is an extra storage-class rule. 24 rules. Each value was checked against official documentation; a rule without a documented source is dropped. | Review findings. |
| D19 | Known lists only | `forbidden` holds **only strings the official documents state explicitly** (e.g. `google`, `g00gle`). Other look-alike spellings and trademarks are not checked; `/llms.txt` and the README say the engine does not replace the provider's final decision. | Reserved-word rules in the documents are open-ended. |
| D20 | Limits spanning several fields | **Conservative.** Cloud SQL instance ID max **67** (98 for `project-id:instance-id` − 30 longest project ID − 1). Azure VM follows the **host name rule**, with a narrow pattern (alphanumerics, dot, hyphen). AWS Name tag measured with `.length` (UTF-16), 1–256, empty rejected. Results mark such limits as conservative in a `note` next to `docUrl`. | Review findings. |
| D21 | Label value characters | GCP label conversion: **lowercase + remove characters outside `[\p{L}\p{N}_-]`** (with the `u` flag — `\p{L}`, not `\p{Ll}`, because Hangul is `Lo`). Korean values survive. Keys are our fixed five and are not checked. | GCP label values allow international characters; the lowercase-start rule applies only to keys. |
| D22 | `seq` and `role` inputs | **Fixed** (`01`, `sync`) in development stages 1–5; no wire fields. Input options are growth stage 2. | Not in the original brief. |
| D23 | Message structure | The engine returns **message codes, not sentences**: each violation, step, label change and context error is `{ code, field?, params? }`, a discriminated union per code (`src/core/messages.ts`; API-only codes in `src/api/codes.ts`). Required `params` are typed per code. Sentences are made by the presentation layer `src/messages/` — the core never imports it. User values in `params` (`from`, `to`, `value`) are display strings; API values are shown via the same 80-character description as before. When several `providers` are invalid there is one message per value (`field: "providers[i]"`). | Sentences inside the engine would force an engine change for every new language, and the UI used to find fields by string prefix. Typed params make a missing parameter a compile error. |
| D24 | Catalog format | The catalog is **TypeScript** (`src/messages/en.ts`): `messages` (one function per code) and `ui` (screen text). **English only**; no language switch and no `Accept-Language`. Another language is one more file filling the same `Catalog` type. The three AWS display names are English data (`VPC (Name tag)` …), not catalog entries. | A mapped type turns a missing code or parameter into a `tsc` error; JSON would need runtime parsing and its own template rules. A switch with one language does nothing. |
| D25 | Wire format (breaking, before release) | `violations`, `steps`, `errors`, `label_violations[p]`, `label_transformed[p]`, `transformed` and `rule.notes` are arrays of **`{ code, field?, params?, message }`**. `reason` is removed (use `steps`); `rule.note` becomes `rule.notes` (always an array). Responses of generate, validate and health carry **`version: { engine, rules }`**. **Every failure** (400, 403, 409, 413, 429, 500) goes through one function and has the shape `{ success: false, errors: [...], supported? }`. The OpenAPI document covers `/health` and 500. | `message` keeps `jq '.violations[].message'` readable. Keeping `reason` next to `steps` would let the two drift. With six separate error paths, one would sooner or later ship without `message`. |
| D26 | Versions | `version.engine` = `package.json` `version` (now **0.1.0**; `src/version.ts` holds the value and a test pins it to `package.json`, so the whole manifest is not bundled). `version.rules` = `RULES_REVISION` in `src/core/revision.ts`, format **`YYYY-MM-DD.N`**, bumped for any change that can give a different name, verdict, suggestion or label for the same input. `src/core/rules-fingerprint.json` stores a sha256 over the rule data and the outputs of a fixed input matrix; a test recomputes it and CI compares it with `main` (fingerprint changed without a new revision, or the reverse, fails). Exports carry the versions: the Terraform locals start with a two-line comment, the tags JSON copy is `{ "version": {…}, "labels": {…} }`, and the share-link hash has a `v` key. | A date alone cannot tell two changes on one day apart, and updating only the fingerprint is caught by comparing with `main`. |
| D27 | Name stability | **The caller pins; the API does not reproduce old rules revisions — it reports the mismatch.** (1) Optional request field `rules_version`: if it differs from the current revision the API answers **409** `request.rules_version_mismatch { requested, current }`; a non-string is 400. (2) The UI share link stores `v`. State read from a link is kept apart from the form: while the form equals the linked state the app does not rewrite the hash (a reload keeps the old `v` and the notice); editing the form drops the link state and the hash gets the current `v`. **Share URL** always uses the current revision. (3) The Terraform example has a `rules_version` variable, `ignore_changes = [name]` on the existing VM `lifecycle`, outputs the real resource name separately from the API candidate, and a pinned mode that skips the API call. Old revisions are not served. | `data "http"` runs on every plan, so a rule change would propose replacing a VM. Serving old revisions would need copies of the rule table. A pinned caller blocked by 409 needs a way out — the pinned mode. |
| D28 | Meaning of PASS | One sentence in four places (UI, `/llms.txt`, OpenAPI `valid`, README): *PASS / `valid: true` means the name satisfies the documented naming checks of this rules revision (length, pattern, reserved words). It does not mean the name is available or that you may create it — uniqueness, permissions, quotas and organisation policy are not checked. Generated names are not guaranteed unique: shortening can map two different contexts to the same name.* The source is `ui.pass_meaning` in `src/messages/en.ts`; tests check the static copies. | Reading PASS as "you can create this" hides the limits in D19 and D20. |
| D29 | Log messages | Log output (`console.error`) is **out of scope** for the message codes. | Logs are not shown to users or agents. |

## Later decisions

| Date | Decision | Why |
|---|---|---|
| 2026-09-28 | Development started in a private repository and was published at release (development stage 5). | Keep in-progress history private until release. |
| 2026-09-28 | Add **`-an`** to the S3 forbidden suffixes (alongside `-s3alias`, `--ol-s3`, `.mrap`, `--x-s3`, `--table-s3`). | The official docs reserve `-an` for account-regional namespace buckets; a general bucket ending in `-an` would be rejected. |
| 2026-09-28 | Azure resource group digits use **`\p{Nd}`**, not `\p{N}`. | The docs limit digits to DecimalDigitNumber; `\p{N}` would accept invalid characters such as `²` (No) or `Ⅻ` (Nl). |
| 2026-09-28 | Add **`aksmanagedap`** to the Linux AKS node pool `forbidden.exact`. | The official FAQ reserves it. Windows node pools are limited to 6 characters, so the 12-character name cannot occur there. |
| 2026-09-28 | GCP VPC, subnet and service account rules cite the **REST reference** (`name` / `accountId` fields) instead of overview pages. | Every rule number must cite a page that states it; the overview pages do not. Values unchanged. |
| 2026-09-28 | AWS tag limits cite **`best-practices-and-strats.html#tag-conventions`**; Azure and GCP tag URLs normalised to the same form. | The previous URL did not contain the numbers. Values (128 / 256) unchanged. |
| 2026-09-28 | GCP Project ID forbids only **`google`** and **`ssl`**; `undefined` and `null` are "avoid" in the docs and are not forbidden. | Promoting advice to a ban would reject names the provider accepts (D19). |
| 2026-09-28 | Conservative: Cloud SQL instance ID keeps the **alphanumeric-end** requirement. | The docs state no end rule and it was not measured; relaxing it risks reporting invalid as valid (D20). |
| 2026-09-28 | Conservative: GCS buckets stay at **63** characters although dotted names may be 222. | Dotted names need domain verification and the engine never generates dots (D20). |
| 2026-09-28 | Conservative: Azure VM (Linux and Windows) requires an **alphanumeric start** and **rejects all dots**. | The docs list `.` as forbidden yet say Linux names "can't end with periods". Allowing inner dots would report invalid as valid if the stricter reading is right (D20). `generate` never produces dots, so output is unchanged. |
| 2026-09-28 | Conservative: AWS Name tag length is measured in **UTF-16 units**, although the docs say "256 Unicode characters". | Stricter only for supplementary-plane characters (e.g. emoji) (D20). |
| 2026-09-28 | Azure tag key limit stays **512**; the storage-account-only 128 limit is not applied. | The engine's tag keys are a fixed five (`owner`, `system`, `purpose`, `environment`, `managed_by`, ≤ 11 characters), far below either limit. |
| 2026-09-28 | Conservative: GCS buckets forbid **consecutive dots (`..`)**. | A bucket name is domain-shaped and cannot have an empty component; rejecting is the safe direction (D20). S3 already forbade `..`. |
| 2026-09-28 | Conservative: Azure resource group names reject **supplementary-plane characters** (U+10000 and above, e.g. `𝔸`). | The docs cite .NET `Char.IsLetterOrDigit`, which on a single UTF-16 unit does not treat surrogate pairs as letters. BMP letters (e.g. Hangul) are still accepted (D20). |
| 2026-09-29 | Conservative: AWS tag values are checked against **`^[\p{L}\p{Z}\p{N}_.:/=+\-@]*$`u**; other characters are reported in `violations`, not stripped. | The general rule in `#tag-conventions`. Checking only length reported `team#1<x>` as valid, which fails on S3/IAM/RDS. EC2 allows more, but the narrower general rule is used (D20). EC2 Name-tag rules are separate. |
| 2026-09-29 | Azure **Windows** VM rejects **all-digit names** (`(?![0-9]+$)`; source URL in `note` via `WINDOWS_COMPUTER_NAME_DOC_URL`). Linux VM and AKS Windows node pools unchanged. | The Windows ComputerName docs forbid names made only of digits; the engine previously returned `12345` as valid. No such rule exists for Linux; AKS node pools already require a leading letter. |
| 2026-09-29 | UI URL-hash limit raised from 4096 to **24675** (`MAX_HASH_CHARS`, computed by formula). | With three fields at 1024 ASCII characters the hash was already 4193, so accepted inputs could not round-trip through a share link. Worst case is control characters / lone surrogates escaped as `\uXXXX` (6 bytes each): 67 + 3×1024×6 = 18499 bytes → 24668 Base64 characters + `#state=` (7). A limit remains to prevent abuse. |
| 2026-09-29 | Azure **reserved words** ([error-reserved-resource-name](https://learn.microsoft.com/en-us/azure/azure-resource-manager/troubleshooting/error-reserved-resource-name)) on storage account, Key Vault, SQL server, VMs and AKS node pools: the 38 listed words are banned as a word (`forbidden.words` — not adjacent to a letter, so `azure123` and `kv-azure-prd` fail, `myazurestore` passes), `microsoft` and `windows` anywhere (`contains`), `login` at the start (`prefixes`), all case-insensitive (`ignoreCase`). Resource group, managed identity, VNet and subnet are not checked. Subnet scope is now `virtual_network`, AKS node pool scope `managed_cluster`. | The engine returned `microsoft123` as a valid storage account. The docs apply the list to resources with an accessible endpoint (storage, Key Vault, SQL have FQDNs); VMs and node pools have no endpoint of their own but their names become host names, so they are checked conservatively (D20). "Whole word" is not defined in the docs; treating any non-letter as a boundary rejects more names than a hyphen-only reading. |
| 2026-09-29 | UI URL-hash limit raised from 24675 to **24699** (`MAX_HASH_CHARS`, still computed by formula; measured by `urlState.test`). | The share link now carries the rules revision as a last key `v` (D26 · D27). The skeleton reserves 13 characters for it (`YYYY-MM-DD.NN`): 87 + 3×1024×6 = 18519 bytes → 24692 Base64 characters + `#state=` (7). |
| 2026-10-06 | **11 rules added** (35 in all; rules revision `2026-10-06.5`) — the resources a single VM serving the internet needs and that were missing. AWS: `internet_gateway`, `route_table`, `ebs_volume` (Name tags, same rule as `vpc`), `security_group`, `key_pair`. GCP: `firewall_rule`, `disk` (RFC 1035, 1–63). Azure: `public_ip`, `network_security_group`, `network_interface` (1–80, same sentence as `subnet`), `os_disk` (1–80, alphanumerics, underscores and hyphens — no dots and no start/end rule). Every rule has hand-picked pass/fail examples in `src/core/__fixtures__/rule-cases.json`. | Each value was re-read from the linked page on 2026-10-06. Azure reserved words are not applied to the four Azure rules: their names do not become DNS names (a public IP's FQDN comes from its separate DNS label). |
| 2026-10-06 | Conservative: AWS security group names reject an **`sg-` prefix in any case** (`SG-web` too). | The page says names are case-insensitive and "Can't start with sg-"; reading the prefix case-sensitively could report a rejected name as valid (D20). |
| 2026-10-06 | Conservative: AWS key pair names accept **printable ASCII only** (`0x20`–`0x7E`); the rule sits at Region scope with a note that the scope is **not confirmed**. | The page says "Up to 255 ASCII characters" and "A unique name for the key pair" without saying within what. Control characters are rejected (D20). |
| 2026-10-06 | **328 Azure rules imported** from the formal rows of [resource-name-rules](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/resource-name-rules) (upstream commit `4966c6cb…`; 343 Azure rules, 363 in all; rules revision `2026-10-06.7`). Rule tables now live in `src/core/rules/{aws,gcp,azure}.ts`; the imported rows are generated into `src/core/rules/azure-intake.ts` by `scripts/rules/build-azure-rules.mjs`. Each distinct *Valid Characters* cell (83) is read with a fixed sentence grammar into one pattern; lengths stay in `minLength`/`maxLength`. Scope values that name a parent resource become scope nodes (71) under the parent row's scope; `region` becomes `azure:region` under the subscription; `resource group & region` is read as resource group. Prefixes come from the Cloud Adoption Framework abbreviation list on an exact, unambiguous match, otherwise from the entity name. Rows with scope `global` get the Azure reserved-word check. 61 rows are held with reasons in `docs/azure-intake-held.md` (37 needing a manual reading, 14 fixed-value, 10 whose scope does not map to one node). | Scope column values have no defining sentence on the page; reading them as the uniqueness scope is an interpretation (as for the first 14 scopes). Reading `resource group & region` as resource group and applying reserved words to global names reject more, never less. Pass/fail examples per row are built from the parsed sentences, not from the regex, and a transcription test checks every imported row against a snapshot of the source table. |
