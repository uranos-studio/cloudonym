## Landing page (`/`)

The home page says what Cloudonym does in one sentence, plays a one-time animated intro of about 3.5 seconds — the five context values, then one name they give, then PASS; with reduced motion only the last frame shows — and offers three cards: **AWS** and **Google Cloud** open the naming wizard at `/aws` and `/gcp`, each with its resource count; **Azure** is disabled with **Coming soon** (there is no `/azure` page). The footer links to Privacy, About, the naming guide, the API page and `llms.txt` (D129).

## Naming wizard (web UI, `/aws` · `/gcp`)

The wizard names a whole AWS account (`/aws`) or Google Cloud project (`/gcp`) (D84, D89, D93, D129; the header's cloud picker switches in place and the address follows, Azure is **Coming soon**). It is three columns — **Plan** (the list), **Edit** (the selected row) and **Names**; below 768 px they are three tabs. A first visit opens on that cloud's example plan — on Google Cloud `demo · payment · prod · asia-northeast3` with the `serverless-web` card (16 names), on AWS the same values in `ap-northeast-2` with the `web`, `lb`, `tg`, `db` and `object` chips (10 names), all PASS — marked **Example** in the Project panel; **Clear** empties it to the Project values (untouched empty fields show no errors, and **Next: what are you building** then opens the first service's cards), and nothing is written to the address bar until you change something (D97, D108). On tablets a bar at the bottom, *View N generated names (Terraform / JSON)*, opens the names drawer; on phones it switches to the Names tab and reads *View N names* (D108, D109). Above the columns a headline — *Generate valid AWS and Google Cloud resource names.* — and one line on what goes in and what comes out stay on every screen width (D113). Below them a short intro shows one read-only example, labelled as output from sample values and not from your inputs — the same four input values and three names they give (Project ID, Cloud Run service, HTTPS forwarding rule), produced by the engine at build time — and one sentence on the order (D107). **About** in the **More** menu opens the `/about` page — what the tool is, the same example, what PASS checks, the source repository, the license, the project status and the versions — which can also show the dismissed intro again; the other pages link to it from the footer (D109). A link opens exactly as it was shared, on its own cloud's path: a link's cloud wins over the path it was opened on, and an older `/#state=…` link moves to `/aws` or `/gcp` (D129). Names are regenerated as you type. The header shows the cloud picker — **Google Cloud** and **AWS** can be picked, **Azure** is disabled with **Coming soon** — and a **Light · Dark · System** screen mode switch (D94). Next to **Share URL** and **Save plan**, a **More** menu holds **Open plan**, **Pick resources**, **Naming guide**, **API**, **llms.txt** and **About** (D104, D107). Below 768 px the header keeps only the logo, the product name, the badges and **More**: Share URL, Save plan and the screen mode switch move into the menu, and Share URL from the menu reports the result under the header (D105).

**Cards** (D93) — after the project values, the first service asks *What are you building?*. A card adds every resource a working setup needs, named and checked: **Website** (a web server VM behind an HTTPS load balancer, HTTP redirected to HTTPS, with the firewall rules the load balancer needs; a database on by default), **Serverless web** (Cloud Run behind a serverless NEG), **Static site** (a bucket behind a backend bucket), **Internal app on VMs** (web, app and database servers with a bastion, and a firewall rule that lets them reach each other) **HTTPS load balancer** (the front only, in front of a web server, Cloud Run service or bucket the service already has), **Data warehouse (BigQuery)** (a landing bucket, a BigQuery dataset — its name uses underscores — and a service account; a Cloud Scheduler job as an option), **GKE cluster** (the cluster, an Artifact Registry repository and a node service account on the VPC network and subnet; Memorystore for Redis as an option), **Event pipeline (Pub/Sub)** (topic, subscription, dead-letter topic with its own subscription, Cloud Run service and service account), **CI/CD (Cloud Build)** (Artifact Registry repository, Cloud Build trigger and service account; a secret and a GitHub connection — a Cloud Build connection and the repository linked through it — as options) and **Batch job** (a Cloud Run job, a Cloud Scheduler job and a service account) (D114). Every card except HTTPS load balancer was built on Google Cloud under its exported names and checked to work as the service it describes (D91, D96, D117); the HTTPS load balancer card alone has no backend to serve. There is no private-network card: its parts are all project-level, and the network section already starts with the VPC network, subnet, Cloud Router and Cloud NAT. One service can hold several cards (D115, D116): cards that need a service account, an Artifact Registry repository, a secret, a Cloud SQL instance or a bastion share the one the service already has — for example Event pipeline, CI/CD and Batch job with one service account, or GKE and CI/CD with one repository — and removing a card keeps a part another card still uses. Where two cards need the same kind of resource for different jobs, the second has its own tier, so both get a name: Internal app on VMs uses internal servers `intweb` and `intwas` and an `appdata` bucket, Event pipeline a private Cloud Run service `worker`, Data warehouse a landing bucket `raw` and a scheduled load job `ingest`. The only pair that cannot share a service is two load balancers — a service has one URL map with one default backend; put the second in another service. Serverless web and Static site also need settings that have no name — public access to the Cloud Run service, and a public, index-page bucket — and their checklists say so with a link to the Google Cloud page. Selecting a card in the list opens its checklist: each part with its name, the network parts it added, and a warning that lists missing parts if you untick one (a load balancer does not serve without them). Removing a card keeps the database option, the network firewall rules and any part another card in the service uses. Cards are not stored: the screen recognises them from the resources a service has, so share links and `POST /v1/wizard` are unchanged.

1. **Project** — type **Owner · System** (at most 64 characters each), pick one or more **Environments** and a **Region** (searching by a zone name also finds its region). The **project name** and the **project ID** (`<owner>-<system>-<env>`) appear at once, one per environment; with several environments the same plan is named once for each. An optional **Project ID suffix** (a team code or a year, e.g. `team1` → `platform-billing-prod-team1`) makes a predictable ID your own: project IDs are unique across Google Cloud and never reusable, and Cloudonym cannot check whether one is free (D85).
2. **Network** (one row in the list; select it to see its parts) — a VPC, subnets, firewall rules (`ssh`, `web`, `icmp`, `iap` for IAP TCP forwarding, `lbhc` for load balancer health checks, `internal` for the web and app ports between servers inside the network, or any other tier you type), a Cloud Router, Cloud NAT and a private services access range (`psa`, a global internal address). The VPC starts as one network (a plan with two, made through the API, still shows both). **Add subnet** adds another subnet with its own kind and tier — for example a proxy-only subnet beside the private one (`…-snet-01`, `…-snet-proxy-01`) (D86, D87, D88).
3. **Services** — one row per service, with its cards folded into one row each. The service name is the `purpose` of every name in that service; **Add service** adds another.
4. **Add more to this service** (a closed section under the cards) — pick resources one at a time: **web**, **was** (app server), **bastion**, **file** (file server), **db** (Cloud SQL), **object** (Cloud Storage), **run** (Cloud Run service), **sa** (service account), **secret** (Secret Manager), **gke** (GKE cluster), **wip** (Workload Identity pool), **bq** (BigQuery dataset), **ar** (Artifact Registry repository), **topic** and **sub** (Pub/Sub), **dlq** (dead-letter topic), **dlqsub** (dead-letter subscription), **build** (Cloud Build trigger), **conn** (Cloud Build connection), **repo** (Cloud Build repository), **cron** (Cloud Scheduler job), **runjob** (Cloud Run job), **redis** (Memorystore for Redis), the second-of-a-kind parts that cards use beside the first (D116): **intweb** and **intwas** (internal web and app servers), **worker** (a private Cloud Run service), **raw** (a landing bucket), **ingest** (a scheduled load job) and **appdata** (an app bucket), or **Custom…**, which opens the resource tree (scopes collapsed; search to find a row) to tick any number of other catalog rows — untick one to remove it, **Done** to close. The **Load balancer** row adds the parts of an HTTPS load balancer one name at a time — global IP address, instance group, backend service, health check, URL map, SSL certificate, target HTTPS proxy and forwarding rule, plus the HTTP-to-HTTPS redirect: a URL map and a forwarding rule with the tier `redir` and a target HTTP proxy; the parts are not linked to one another.
5. **Options and servers** — web and app servers can be **Serverless** (Cloud Functions or Cloud Run) or **HA** (at least two servers); a resource with kinds takes its kind (a database its engine, a GKE cluster Standard or Autopilot), and a service account its role (`sync` when left empty). Each server is one line with its own number: removing server 01 does not rename server 02, and **Renumber** closes the gaps only when you ask; other numbered resources add a line with **Add Cloud SQL Instance** and so on (a subnet: **Add number (same kind and tier)**). A pick without a fixed tier (a bucket, a database, a custom pick) takes an optional **Tier**, and **Duplicate** copies it without the tier so one service can hold two of a kind — for example buckets `…-gcs-uploads` and `…-gcs-backups`. A bucket or BigQuery dataset pick has a **Location** select: the project region by default, or a multi-region or dual-region location (`US` → `…-prod-us-gcs`). A secret pick has one too: **Global** by default, with no region token (`…-prod-secret-01`), or **Regional** for a regional secret in the project region (`…-prod-ane3-secret-01`).
6. **Attached resources** — per server, a **boot** disk, numbered **data** disks and reserved external or internal addresses (**ip**, **ipi**). Their names continue the server's name.
**Shared extra resources** (no number) — **Custom…** here picks any other project-level resource that is not tied to one service.
7. **Names** — one short row per name, grouped by project and service, attached resources under their server, each with `PASS`/`FAIL` and the reasons; the rule (length, characters, official doc, pattern) opens on the ⓘ button. Copy **all names**, the **JSON**, **Terraform** `locals` (one map `gcp_names` keyed by the item key, plus `gcp_labels_by_namespace`) or the **Share URL**. With several environments the names are grouped by environment first, the JSON has one entry per environment under `environments`, and Terraform gives `gcp_names_by_env` and `gcp_labels_by_env` (environment → item key or namespace). `POST /v1/wizard` still takes one environment per request. A valid bucket name has a **Check** button (here and on `/pick`): when you click it, your browser asks Cloud Storage directly whether the name is taken (available · taken · could not tell); the name never goes to Cloudonym.

For example, project `platform` · `billing` · `prod` · `asia-northeast3` with a VPC network, a service `shop` (web server 01 with a boot disk and data disk 01, and a PostgreSQL database) and a service `pay` (web servers 01 and 02 with HA) gives these names — the same request is the [`POST /v1/wizard` example](api.md#whole-project-post-v1wizard) below:

```text
platform-billing-prod                        project ID
billing-prod-vpc-01                          VPC network (project level: no service, no region)
billing-shop-prod-ane3-gce-web-01            web server 01 of shop
billing-shop-prod-ane3-gce-web-01-boot       its boot disk
billing-shop-prod-ane3-gce-web-01-data-01    its data disk 01
billing-shop-prod-ane3-sql-pg-01             Cloud SQL (PostgreSQL)
billing-pay-prod-ane3-gce-web-01             web server 01 of pay
billing-pay-prod-ane3-gce-web-02             web server 02 of pay
```

The wizard and its preset groups — web, app and bastion servers; file server; database; object storage; Cloud Run service; service account; secret; GKE cluster; Workload Identity pool; load balancer parts; network — are part of this repository, and any other catalog row is a custom pick. More complex stacks are out of scope for this repository.

### Name formula

Most numbered resources follow `<system>-<purpose>-<env>-<region>-<abbreviation>[-<kind>][-<tier>]-<seq>`; every formula in use is listed on `/docs/naming` and in `/llms.txt`.

- `region` is a region code (`ane3`), never a zone — a zone you enter resolves to its region, so VMs and disks are named like regional resources. Resources without a location (a service account, Workload Identity pools, deny policies, policy bindings and workforce pools, whose only location is `global`) and children that inherit their parent's location (a KMS key, a Spanner database, a Cloud SQL user, Cloud NAT) carry no region token (D77); a Cloud Storage bucket or BigQuery dataset can carry a multi-region or dual-region code instead (`us`, `asia1`; D78); a Secret Manager secret is global unless the wizard pick asks for a regional secret (D79).
- `kind` is added only when it differs from the provider default (`pg` for PostgreSQL).
- `tier` (`web`, `was`, …; pattern `^[a-z0-9]{2,16}$`) is filled only by the wizard, so `/v1/generate` and `/v1/names` never put one in a name. It is never shortened. Numbered resources take it before the sequence number; resources with neither a sequence number nor a role (a bucket, a BigQuery dataset) take it right after the abbreviation, which is how two buckets in one service differ (`platform-billing-shop-prod-ane3-gcs-uploads`, `…-gcs-backups`). Abbreviations, kind tokens, environment values and region codes are not allowed as tiers.
- Attached resources add `-boot`, `-data-<seq>`, `-ip` or `-ipi` to the server's final name and are never shortened; a name that does not fit fails with the reason.

## Pick resources (`/pick`)

The resource tree is at `/pick` (**Pick resources** in the header's **More** menu); a tree link opened at `/` moves there. It names single resources from one set of five values, in four steps:

1. **① Cloud** — pick AWS or GCP. Azure is shown as **Coming soon** and cannot be picked yet.
2. **② Context** — type **Owner · System · Purpose** (at most 64 characters each), pick **Environment**, and pick a **Region** (searching by a zone name also finds its region). Names are regenerated as you type.
3. **③ Resources** — a tree of the provider's resources, grouped by the scope in which the provider requires a name to be unique. Search by name, id, Terraform type, gcloud group or alias, filter by category, or show the selected rows only. Each row has an ⓘ with a one-line description and where the name is entered (gcloud flag or Terraform argument); rows marked **API only** have no gcloud command or Terraform resource and are created through the API. Tick a resource and set how many you need (1–99, numbered `01`…`99`); resources without a sequence number are always one, and identity-like resources take a short role (`sync` by default). A row that covers several scopes (for example a regional and a global address) asks for the scope first, and some rows take a **kind** (for example the Cloud SQL engine).
4. **④ Names** — only the picked resources, grouped by scope, each with `PASS`/`FAIL` and why it was shortened or transformed. Copy one name, **all valid names** (one per line), the **names JSON** or **Terraform locals** (names and tags). The **Tags · Labels** panel copies the provider's standard tags as JSON. Two picked resources that would get the same name in the same scope are both marked `FAIL` (`name.conflict`).

One line above the names says what **PASS** means (see [What PASS means](api.md#what-pass-means)). The footer shows the engine and rules versions; a share link made with older rules shows a notice until you change the input.

Allowed values — env: `prod` · `stg` · `dev` · `sbx` · `qa` · `uat` · `test` · `perf` · `dr` (aliases such as `prd`, `production`, `staging`, `acceptance`, `performance`, `recovery` are accepted and normalised) · region: a region or a zone of the provider, by name or by code (`asia-northeast3`, `asia-northeast3-a`, `ane3`, `ane3a`), or `global` — a zone is accepted and resolved to its region (names carry the region code, never a zone), and global resources carry no region token. The old country values `kr` and `jp` are rejected with the matching region names. Multi-region and dual-region locations (`US`, `EU`, `ASIA`, `ASIA1`, `EUR4`, `EUR5`, `EUR7`, `EUR8`, `NAM4`; by name or code) are accepted only for the types that take them — `storage_bucket` all nine, `bigquery_dataset` `US` and `EU` — so `/v1/names` takes one when every requested type with a region token supports it, and `/v1/generate` (every type) answers 400 `context.location_unsupported`. The locations and the types that take them are listed in `/llms.txt`. The region table is in `/llms.txt` and on the naming guide page `/docs/naming`.

### Share URL — your input is readable by anyone with the link

Both screens keep their state in the URL hash — the wizard its project values, services, picks and servers; the tree the five values, the provider and the selection — and **Share URL** copies that link. The hash is written to the address bar as you type, even if you never press the button. It is **Base64, not encryption**: anyone who gets the link can decode it and read owner, system, the service names and the rest. Do not enter sensitive values such as internal company or project names if you plan to share the link. The wizard shows the same warning in its first-visit note and again when you press the button; the tree shows it next to the button.

### Plan file — Save plan and Open plan

**Save plan** (in the wizard's header, next to Share URL; in the **More** menu below 768 px) downloads the plan as `cloudonym-plan-<system>-<env>.json`. The file is the `POST /v1/wizard` request body — `provider`, `project`, `project_id_suffix`, `project_picks`, `services` — plus `rules_version` (the rules revision when you saved) and, when the plan has two or more environments, `environments` (`project.env` is the first). It holds the same plan as the share link, so the same warning applies: it is plain JSON, readable by anyone you give it to. **Open plan** (in the header's **More** menu) loads such a file and replaces the current plan; it is repaired and reported the same way as a link (an invalid pick is left out and counted, a file that is not a plan changes nothing, and a file saved with other rules says so). Fields it does not know are ignored, as `POST /v1/wizard` ignores them, and counted in one line, so the same file gives the same names on the web and from the API (an `attach` with an unknown field is the exception: the API rejects it, and Open plan leaves that `attach` out). Files larger than 176,558 bytes — the most a share link can hold — are not read, and a file or link with more than 400 picks, or more than 400 servers and data disks, is not repaired: only its project values are kept.

```json
{
  "provider": "gcp",
  "project": { "owner": "platform", "system": "billing", "env": "prod", "region": "ane3" },
  "project_picks": [{ "preset": "vpc", "instances": [{ "id": "1", "seq": "01" }] }],
  "services": [{ "purpose": "shop", "picks": [{ "preset": "db", "kind": "POSTGRES", "instances": [{ "id": "1", "seq": "01" }] }] }],
  "rules_version": "2026-10-25.4",
  "environments": ["prod", "stg"]
}
```

Send the file as it is: `curl -s -X POST https://<your-deployment>/v1/wizard -H 'content-type: application/json' -d @cloudonym-plan-billing-prod.json`. The API ignores `environments` and names `project.env` only — send one request per environment with `project.env` changed. `rules_version` pins the request (409 if the rules have changed since you saved). Request bodies may be up to 32 KB; a saved file is indented, so for a very large plan send it compact (`jq -c . file.json | curl … -d @-`). The JSON Schema of the file is served at `/plan.schema.json`.

## 소개 페이지 (`/`)

첫 화면은 Cloudonym 이 하는 일을 한 문장으로 말하고, 한 번만 도는 약 3.5초의 움직이는 소개 — 다섯 문맥값 → 그 값이 만드는 이름 하나 → PASS. 움직임을 줄인 기기는 마지막 장면만 — 를 보인 뒤 카드 셋을 낸다. **AWS** · **Google Cloud** 는 이름 마법사 `/aws` · `/gcp` 를 열고 각자 리소스 수를 보인다. **Azure** 는 **Coming soon** 으로 꺼져 있다(`/azure` 쪽은 없다). 꼬리에서 Privacy · About · 이름 안내 · API · `llms.txt` 로 간다(D129).

## 이름 마법사 (웹 화면 `/aws` · `/gcp`)

마법사는 AWS 계정 하나(`/aws`) 또는 Google Cloud 프로젝트 하나(`/gcp`)의 이름을 짓는다(D84 · D89 · D93 · D129 · 머리의 클라우드 단추로 화면 안에서 바꾸면 주소가 따라가고, Azure 는 **Coming soon**). 세 칸이다 — **Plan**(목록) · **Edit**(고른 줄) · **Names**. 768px 아래에서는 탭 셋이다. 처음 오면 그 클라우드의 예시 계획으로 열린다 — Google Cloud 는 `demo · payment · prod · asia-northeast3` 에 `serverless-web` 카드(이름 16개), AWS 는 같은 값에 지역 `ap-northeast-2` 와 칩 `web` · `lb` · `tg` · `db` · `object`(이름 10개), 모두 PASS 이고 Project 칸에 **Example** 표시가 붙는다. **Clear** 를 누르면 Project 값이 빈 칸으로 돌아가고(손대지 않은 빈 칸에는 오류를 띄우지 않고, 값이 맞으면 **Next: what are you building** 이 첫 서비스의 카드로 데려간다), 무엇이든 바꾸기 전에는 주소창에 아무것도 쓰지 않는다(D97 · D108). 태블릿에서는 아래 막대 *View N generated names (Terraform / JSON)* 이 이름 서랍을 연다(D108). 링크는 공유한 그대로, 그 링크의 클라우드 경로에서 열린다 — 링크의 클라우드가 연 경로보다 이기고, 옛 `/#state=…` 링크는 `/aws` · `/gcp` 로 옮겨 간다(D129). 입력하는 대로 이름이 다시 만들어진다. 머리에는 클라우드 단추가 있다 — **Google Cloud** · **AWS** 를 고를 수 있고, **Azure** 는 **Coming soon** 으로 꺼져 있다. 그리고 **Light · Dark · System** 화면 모드를 고를 수 있다(D94). **Share URL** · **Save plan** 곁의 **More** 메뉴에 **Open plan** · **Pick resources** · **Naming guide** · **API** · **llms.txt** · **About** 가 있다(D104). About 은 `/about` 쪽 — 무엇인가 · 예시 · PASS 가 보는 것과 안 보는 것 · 소스 저장소 · 라이선스 · 프로젝트 상태 · 버전 — 이고, 다른 쪽은 푸터에서 간다(D109). 폰의 아래 이름 막대는 짧은 글 *View N names* 다. 768px 아래에서는 머리에 로고 · 제품 이름 · 배지 · **More** 만 남고, Share URL · Save plan · 화면 모드도 메뉴로 들어간다. 메뉴의 Share URL 은 결과를 머리 아래에 알린다(D105).

**카드**(D93) — 프로젝트 값을 채운 뒤 첫 서비스에서 *What are you building?* 을 묻는다. 카드 하나가 동작하는 구성에 필요한 리소스를 이름과 판정까지 한 번에 더한다 — **Website**(HTTPS 로드 밸런서 뒤의 웹 서버 VM, HTTP 는 HTTPS 로 전환, 로드 밸런서에 필요한 방화벽 규칙까지 · 데이터베이스는 기본으로 켜짐) · **Serverless web**(서버리스 NEG 뒤의 Cloud Run) · **Static site**(백엔드 버킷 뒤의 버킷) · **Internal app on VMs**(웹 · 앱 · DB 서버와 bastion, 서버끼리 닿게 하는 방화벽 규칙) · **HTTPS load balancer**(서비스에 이미 있는 웹 서버 · Cloud Run · 버킷 앞에 앞쪽만) · **Data warehouse (BigQuery)**(적재용 버킷 · 이름에 밑줄을 쓰는 BigQuery 데이터셋 · 서비스 계정, 선택으로 Cloud Scheduler 작업) · **GKE cluster**(VPC 네트워크와 서브넷 위의 클러스터 · Artifact Registry 저장소 · 노드 서비스 계정, 선택으로 Memorystore for Redis) · **Event pipeline (Pub/Sub)**(토픽 · 구독 · 데드레터 토픽과 그 구독 · Cloud Run 서비스 · 서비스 계정) · **CI/CD (Cloud Build)**(Artifact Registry 저장소 · Cloud Build 트리거 · 서비스 계정, 선택으로 시크릿 · GitHub 연결 — Cloud Build 연결과 그것으로 이은 저장소) · **Batch job**(Cloud Run 작업 · Cloud Scheduler 작업 · 서비스 계정)(D114). HTTPS load balancer 를 뺀 카드는 전부 내보낸 이름 그대로 Google Cloud 에 만들어 설명한 서비스로 동작하는지 시험했다(D91 · D96 · D117). HTTPS load balancer 카드는 혼자서는 응답할 백엔드가 없다. 사설 네트워크 카드는 없다 — 부품이 전부 프로젝트 공용이고, 네트워크 칸이 이미 VPC 네트워크 · 서브넷 · Cloud Router · Cloud NAT 로 시작한다. 한 서비스에 카드 여럿을 둘 수 있다(D115 · D116) — 서비스 계정 · Artifact Registry 저장소 · 시크릿 · Cloud SQL 인스턴스 · bastion 은 서비스에 있는 것을 카드들이 함께 쓴다(예: Event pipeline · CI/CD · Batch job 이 서비스 계정 하나, GKE 와 CI/CD 가 저장소 하나). 카드를 지워도 다른 카드가 쓰는 부품은 남는다. 두 카드가 같은 종류의 리소스를 서로 다른 일에 쓰면 둘째 것은 tier 를 따로 달아 이름이 둘 나온다 — Internal app on VMs 는 내부 서버 `intweb` · `intwas` 와 버킷 `appdata`, Event pipeline 은 비공개 Cloud Run `worker`, Data warehouse 는 적재 버킷 `raw` 와 예약 적재 작업 `ingest`. 한 서비스에 함께 둘 수 없는 것은 로드 밸런서 둘뿐이다 — 서비스에 URL 맵이 하나이고 그 기본 백엔드도 하나다. 둘째는 다른 서비스에 둔다. Serverless web 과 Static site 는 이름이 없는 설정도 필요하다 — Cloud Run 서비스의 공개 호출 허용, 버킷의 공개 읽기와 기본 문서 — 점검표가 그것을 Google Cloud 문서 링크와 함께 말한다. 목록에서 카드를 고르면 점검표가 열린다 — 부품마다 이름, 네트워크에 더한 부품, 하나를 빼면 빠진 부품을 말하는 경고(로드 밸런서는 그것 없이 응답하지 않는다). 카드를 지워도 데이터베이스 선택 · 네트워크 방화벽 규칙 · 서비스의 다른 카드가 쓰는 부품은 남는다. 카드는 저장하지 않는다 — 화면이 서비스에 있는 리소스에서 알아보므로 공유 링크와 `POST /v1/wizard` 는 그대로다.

1. **Project** — **Owner · System** 을 적고(각 64자까지) **Environments** 를 하나 이상 · **Region** 을 고른다(존 이름으로 찾아도 그 리전이 나온다). **프로젝트 이름**과 **프로젝트 ID**(`<owner>-<system>-<env>`)가 환경마다 바로 보인다. 환경을 여럿 고르면 같은 계획을 환경마다 한 번씩 짓는다. 선택 칸 **Project ID suffix**(팀 코드나 연도 — `team1` → `platform-billing-prod-team1`)는 예측할 수 있는 ID 를 내 것으로 만든다 — 프로젝트 ID 는 Google Cloud 전체에서 유일하고 다시 쓸 수 없으며, Cloudonym 은 그 ID 가 비어 있는지 확인할 수 없다(D85)
2. **Network**(목록에서 한 줄 · 고르면 부품이 보인다) — VPC · 서브넷 · 방화벽 규칙(`ssh` · `web` · `icmp` · IAP TCP forwarding 용 `iap` · 로드 밸런서 상태 확인용 `lbhc` · 네트워크 안의 서버끼리 웹 · 앱 포트를 여는 `internal`, 또는 직접 적은 tier) · Cloud Router · Cloud NAT · private services access 대역(`psa`, 전역 내부 주소). VPC 는 하나로 시작한다(둘이 든 링크는 둘 다 보인다). **Add subnet** 은 종류와 tier 를 따로 갖는 서브넷을 하나 더 둔다 — 예: 사설 서브넷 옆의 프록시 전용 서브넷(`…-snet-01` · `…-snet-proxy-01`) (D86 · D87 · D88)
3. **Services** — 서비스마다 한 줄, 그 안의 카드는 카드마다 한 줄로 접힌다. 서비스 이름이 그 서비스 안 모든 이름의 `purpose` 다. **Add service** 로 더한다
4. **Add more to this service**(카드 아래 접힌 칸) — 리소스를 하나씩 고른다 — **web** · **was**(앱 서버) · **bastion** · **file**(파일 서버) · **db**(Cloud SQL) · **object**(Cloud Storage) · **run**(Cloud Run 서비스) · **sa**(서비스 계정) · **secret**(Secret Manager) · **gke**(GKE 클러스터) · **wip**(Workload Identity pool) · **bq**(BigQuery 데이터셋) · **ar**(Artifact Registry 저장소) · **topic** · **sub**(Pub/Sub) · **dlq**(데드레터 토픽) · **dlqsub**(데드레터 구독) · **build**(Cloud Build 트리거) · **conn**(Cloud Build 연결) · **repo**(Cloud Build 저장소) · **cron**(Cloud Scheduler 작업) · **runjob**(Cloud Run 작업) · **redis**(Memorystore for Redis), 카드가 첫째 것 옆에 두는 둘째 것(D116) — **intweb** · **intwas**(내부 웹 · 앱 서버) · **worker**(비공개 Cloud Run 서비스) · **raw**(적재 버킷) · **ingest**(예약 적재 작업) · **appdata**(앱 버킷), 또는 리소스 트리를 열어 다른 catalog 행을 여러 개 고르는 **Custom…**(범위는 접힌 채 열리고 검색으로 행을 찾는다 · 체크를 풀면 지워지고 **Done** 으로 닫는다). **Load balancer** 줄은 HTTPS 로드 밸런서 부품을 이름 하나씩 더한다 — 전역 IP 주소 · 인스턴스 그룹 · 백엔드 서비스 · 상태 확인 · URL 맵 · SSL 인증서 · 대상 HTTPS 프록시 · 전달 규칙, 그리고 HTTP 를 HTTPS 로 돌려보내는 전환용 URL 맵 · 대상 HTTP 프록시 · 80 포트 전달 규칙(전환용 둘은 tier `redir`). 부품끼리 엮지는 않는다
5. **Options and servers** — web · was 서버는 **Serverless**(Cloud Functions · Cloud Run)나 **HA**(서버 두 대 이상)로 바꿀 수 있고, 종류가 있는 리소스는 종류를 고르고(데이터베이스는 엔진, GKE 클러스터는 Standard · Autopilot) 서비스 계정은 역할을 적는다(비우면 `sync`). 서버는 한 줄에 하나, 저마다 번호를 갖는다 — 서버 01 을 지워도 서버 02 의 이름은 그대로이고, 빈 번호는 **Renumber** 를 누를 때만 당긴다. 다른 번호 붙은 리소스는 **Add Cloud SQL Instance** 처럼 그 이름으로 줄을 더한다(서브넷은 **Add number (same kind and tier)**). tier 가 정해지지 않은 pick(버킷 · 데이터베이스 · custom)은 **Tier** 를 적을 수 있고, **Duplicate** 로 복사하면 한 서비스에 같은 종류를 둘 둔다 — 예: 버킷 `…-gcs-uploads` · `…-gcs-backups`. 버킷 · BigQuery 데이터셋 pick 에는 **Location** 고르기가 있다 — 기본은 프로젝트 지역, 멀티 · 이중 리전 위치를 고르면 그 코드가 든다(`US` → `…-prod-us-gcs`). Secret pick 에도 있다 — 기본은 **Global** 이라 지역 토큰이 없고(`…-prod-secret-01`), **Regional** 을 고르면 프로젝트 지역의 지역 Secret 이 된다(`…-prod-ane3-secret-01`)
6. **Attached resources** — 서버마다 **boot** 디스크 · 번호 붙은 **data** 디스크 · 예약 고정 외부 · 내부 주소(**ip** · **ipi**). 이름은 서버 이름을 잇는다
**Shared extra resources**(번호 없음) — 여기의 **Custom…** 은 서비스 하나에 묶이지 않는 프로젝트 수준의 다른 리소스를 고른다
7. **Names** — 이름 하나에 짧은 줄 하나, 프로젝트 → 서비스로 묶고 딸린 리소스는 서버 아래에 보인다. 줄마다 `PASS`/`FAIL` 과 이유가 있고, 규칙(길이 · 문자 · 공식 문서 · 정규식)은 ⓘ 단추로 편다. **이름 전부** · **JSON** · **Terraform** `locals`(항목 키를 맵 키로 하는 맵 `gcp_names` 하나와 `gcp_labels_by_namespace`) · **Share URL** 을 복사한다. 환경이 여럿이면 이름은 환경으로 먼저 묶이고, JSON 은 `environments` 아래 환경마다 하나, Terraform 은 `gcp_names_by_env` · `gcp_labels_by_env`(환경 → 항목 키 · 이름공간)다. `POST /v1/wizard` 는 요청마다 환경 하나 그대로다. 유효한 버킷 이름에는 **Check** 단추가 있다(여기와 `/pick`) — 누르면 브라우저가 Cloud Storage 에 그 이름이 쓰이고 있는지 직접 묻는다(available · taken · 모름). 이름은 Cloudonym 에 가지 않는다

예 — 프로젝트 `platform` · `billing` · `prod` · `asia-northeast3` 에 VPC 네트워크, 서비스 `shop`(boot 디스크 · data 디스크 01 이 붙은 web 서버 01 과 PostgreSQL 데이터베이스), 서비스 `pay`(HA 로 web 서버 01 · 02)를 두면 위 [Naming wizard](#naming-wizard) 의 여덟 이름이 나온다. 같은 요청이 아래 `POST /v1/wizard` 예시다.

마법사와 프리셋 묶음 — web · was · bastion 서버, 파일 서버, 데이터베이스, 오브젝트 스토리지, Cloud Run 서비스, 서비스 계정, 시크릿, GKE 클러스터, Workload Identity pool, 로드 밸런서 부품, 네트워크 — 은 이 저장소에 있고, 그 밖의 catalog 행은 Custom 으로 고른다. 더 복잡한 구성은 이 저장소의 범위 밖이다.

**이름 공식** — 순번이 있는 리소스 대부분은 `<system>-<purpose>-<env>-<region>-<약어>[-<kind>][-<tier>]-<seq>` 이다. 쓰이는 공식 전부는 `/docs/naming` 과 `/llms.txt` 에 있다.

- `region` 은 리전 코드(`ane3`)이고 존은 들지 않는다 — 입력한 존은 그 리전으로 풀려 VM · 디스크도 리전 리소스처럼 이름 붙는다. 위치가 없는 리소스(서비스 계정 · Workload Identity 풀 · 거부 정책, 위치가 `global` 하나인 policy binding · workforce pool)와 부모의 위치를 물려받는 자식(KMS 키 · Spanner 데이터베이스 · Cloud SQL 사용자 · Cloud NAT)에는 지역 토큰이 없다(D77). Cloud Storage 버킷 · BigQuery 데이터셋은 멀티 · 이중 리전 코드(`us` · `asia1`)를 대신 가질 수 있다(D78). Secret Manager secret 은 마법사 pick 이 지역 Secret 을 고르지 않으면 전역이다(D79)
- `kind` 는 CSP 기본값과 다를 때만 붙는다(PostgreSQL 은 `pg`)
- `tier`(`web` · `was` …, 꼴 `^[a-z0-9]{2,16}$`)는 마법사만 채운다 — `/v1/generate` · `/v1/names` 의 이름에는 들지 않는다. 줄이지 않는다. 순번이 있는 리소스는 순번 앞에, 순번도 역할도 없는 리소스(버킷 · BigQuery 데이터셋)는 약어 바로 뒤에 든다 — 한 서비스의 버킷 둘이 이렇게 나뉜다(`platform-billing-shop-prod-ane3-gcs-uploads` · `…-gcs-backups`). 약어 · 종류 토큰 · 환경 값 · 지역 코드는 tier 로 쓸 수 없다
- 딸린 리소스는 서버의 최종 이름에 `-boot` · `-data-<seq>` · `-ip` · `-ipi` 를 붙이고 줄이지 않는다 — 들어가지 않으면 이유와 함께 실패한다

## 리소스 고르기 (`/pick`)

리소스 트리는 `/pick`(머리 **More** 메뉴의 **Pick resources**)에 있고, 마법사 전에 나간 공유 링크도 이 화면으로 열린다. 다섯 값 한 벌로 리소스를 하나씩 네 단계로 짓는다.

1. **① Cloud** — AWS 나 GCP 를 고른다. Azure 는 **Coming soon** 표지와 함께 보이고 아직 고를 수 없다
2. **② Context** — **Owner · System · Purpose** 를 적고(각 64자까지) **Environment** 를 고르고, **Region** 을 고른다(존 이름으로 찾아도 그 리전이 나온다). 입력하는 대로 이름이 다시 만들어진다
3. **③ Resources** — CSP 가 이름을 유일하게 요구하는 범위로 묶은 리소스 트리다. 이름 · id · Terraform 타입 · gcloud 그룹 · 별칭으로 찾고, 분류로 거르고, 고른 행만 볼 수 있다. 행마다 ⓘ 에 한 줄 설명과 이름을 넣는 자리(gcloud 플래그 · Terraform 인자)가 있고, **API only** 표지가 붙은 행은 gcloud 명령 · Terraform 리소스가 없어 API 로 만든다. 체크하고 개수(1~99 · 순번 `01`…`99`)를 정한다. 순번이 없는 리소스는 늘 하나이고, ID 성격의 리소스는 짧은 역할(기본 `sync`)을 받는다. 범위가 여럿인 행(지역 주소와 전역 주소 등)은 범위부터 고르고, 어떤 행은 **종류**(Cloud SQL 엔진 등)를 받는다
4. **④ Names** — 고른 리소스만 범위별로 보이고, 카드마다 `PASS`/`FAIL` 과 줄이거나 바꾼 이유가 나온다. 이름 하나 · **유효한 이름 전부**(한 줄에 하나) · **이름 JSON** · **Terraform locals**(이름 + 태그)를 복사한다. **Tags · Labels** 칸은 CSP 표준 태그를 JSON 으로 복사한다. 같은 범위에서 같은 이름이 될 두 리소스는 둘 다 `FAIL`(`name.conflict`)이다

이름 위 한 줄이 **PASS** 의 뜻을 말한다(쓸 수 있는지 · 고유한지는 검사하지 않는다). 꼬리말에 엔진 · 규칙 버전이 있고, 옛 규칙으로 만든 공유 링크는 입력을 바꿀 때까지 안내를 보인다.

**공유 URL 주의** — 두 화면 모두 상태를 URL hash 에 둔다(마법사는 프로젝트 값 · 서비스 · 고른 것 · 서버, 트리는 다섯 값 · CSP · 선택). **Share URL** 은 그 링크를 복사한다. hash 는 버튼을 누르지 않아도 입력하는 대로 주소창에 쓰인다. **Base64 는 암호화가 아니다** — 링크를 받은 사람은 owner · system · 서비스 이름 등 입력값을 그대로 읽는다. 링크를 넘길 생각이면 회사 내부 이름 같은 민감한 값을 넣지 않는다. 마법사는 첫 방문 안내 한 줄과 단추를 누를 때 같은 경고를 보이고, 트리 화면은 버튼 옆에 보인다.

**계획 파일** (D100) — 마법사 머리의 **Save plan**(Share URL 곁 · 768px 아래에서는 **More** 메뉴 안)은 계획을 `cloudonym-plan-<system>-<env>.json` 으로 내려준다. 파일은 `POST /v1/wizard` 요청 본문(`provider` · `project` · `project_id_suffix` · `project_picks` · `services`)에 `rules_version`(저장할 때의 규칙 버전)과, 환경이 둘 이상이면 `environments`(첫째가 `project.env`)를 더한 것이다. 공유 링크와 같은 계획을 담으므로 같은 경고가 해당한다 — 평문 JSON 이라 받은 사람이 그대로 읽는다. **Open plan**(머리 **More** 메뉴)은 그 파일을 읽어 지금 계획을 바꾼다. 링크를 열 때와 같이 고치고 알린다(틀린 pick 은 빼고 세며, 계획이 아닌 파일은 아무것도 바꾸지 않고, 다른 규칙 버전으로 저장한 파일은 그 사실을 한 줄로 알린다). 모르는 칸은 `POST /v1/wizard` 처럼 무시하고 몇 개인지 한 줄로 알린다 — 같은 파일이면 웹과 API 가 같은 이름을 낸다(`attach` 안의 모르는 칸만 예외다: API 가 거부하므로 Open plan 은 그 `attach` 를 뺀다). 176,558 바이트(공유 링크가 담을 수 있는 최대)보다 큰 파일은 읽지 않고, pick 이 400개를 넘거나 서버 · 데이터 디스크가 400개를 넘는 파일 · 링크는 고치지 않고 프로젝트 값만 남긴다. 파일은 그대로 보낼 수 있다 — `curl -s -X POST https://<your-deployment>/v1/wizard -H 'content-type: application/json' -d @cloudonym-plan-billing-prod.json`. API 는 `environments` 를 읽지 않고 `project.env` 하나로 이름을 낸다 — 환경마다 `project.env` 를 바꿔 한 번씩 보낸다. `rules_version` 이 요청을 고정한다(저장한 뒤 규칙이 바뀌었으면 409). 본문은 32KB 까지다. 내려받은 파일은 들여쓰기가 있으므로 아주 큰 계획은 압축해 보낸다(`jq -c . file.json | curl … -d @-`). 파일의 JSON Schema 는 `/plan.schema.json` 이다.

허용값 — env: `prod` · `stg` · `dev` · `sbx` · `qa` · `uat` · `test` · `perf` · `dr`(`prd` · `production` · `staging` · `acceptance` · `performance` · `recovery` 같은 별칭도 받아 표준값으로 바꾼다) · region: 그 CSP 의 리전 · 존을 이름이나 코드로(`asia-northeast3` · `asia-northeast3-a` · `ane3` · `ane3a`) 또는 `global` — 존은 받아 그 리전으로 푼다(이름에는 리전 코드만 들고 존은 들지 않는다). 전역 리소스에는 지역 토큰이 없다. 옛 나라 값 `kr` · `jp` 는 거부하고 해당 리전 이름을 알려 준다. 멀티 · 이중 리전 위치(`US` · `EU` · `ASIA` · `ASIA1` · `EUR4` · `EUR5` · `EUR7` · `EUR8` · `NAM4`, 이름이나 코드)는 그 위치를 받는 리소스에만 쓴다 — `storage_bucket` 은 아홉 전부, `bigquery_dataset` 은 `US` · `EU`. `/v1/names` 는 지역 토큰이 있는 요청 리소스가 전부 그 위치를 받을 때만 받고, 리소스 전부를 내는 `/v1/generate` 는 400 `context.location_unsupported` 로 답한다. 위치와 그 위치를 받는 리소스는 `/llms.txt` 에 있다. 지역 표는 `/llms.txt` 와 이름 안내 쪽 `/docs/naming` 에 있다.
