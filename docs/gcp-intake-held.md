## How the imported rows were mapped

- **Compute Engine** — one row per `insert` method whose request schema has a writable `name` with the RFC 1035 `pattern` (`[a-z](?:[-a-z0-9]{0,61}[a-z0-9])?`, 1–63 characters). The scope comes from the method path: `projects/{project}/global/…` → project global, `regions/{region}/…` → project region, `zones/{zone}/…` → project zone. `docUrl` is the REST reference anchor `<Schema>.FIELDS.name` on the collection page; when that page has no such anchor, the request-body anchor on its `insert` page (`body.request_body.FIELDS.name`). Both were checked on 2026-10-06.
- **Cloud KMS** — one row per `create` method of a surveyed asset type whose `…Id` parameter description says "match the regular expression `…`". The expression is accepted only if it is inside backticks, starts with a character class or `^`, has balanced brackets and compiles. The scope comes from the same sentence: "unique within a location" → a project location node, "unique within a KeyRing" → a key ring node.
- **Prefix (slug)** — the initials of the schema name when it has two or more words (`TargetHttpsProxy` → `thp`), otherwise its first three letters (`Router` → `rou`). Same rule as the Azure fallback.
