## How the imported rows were mapped

- **Pattern** — each distinct *Valid Characters* cell is read with a fixed sentence grammar (character kinds, `Can't use:` lists, start/end sentences, consecutive hyphens). A sentence outside the grammar stops the generator; nothing is guessed. Lengths are checked by `minLength`/`maxLength`.
- **Scope** — `resource group` · `global` · `subscription` map to the existing scope nodes; `region` / `Azure region` map to a new `azure:region` node under the subscription; `resource group & region` is read as resource group (stricter). Any other value names a parent resource (`service`, `namespace`, …): a scope node is created for the parent entity, placed under the parent row's own scope.
- **Prefix (slug)** — the abbreviation from the Microsoft Cloud Adoption Framework [abbreviation list](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ready/azure-best-practices/resource-abbreviations) when the namespace/entity matches exactly (entries split by `kind` are skipped). Otherwise: the initials of the last entity segment when it has two or more words (`authorizationServers` → `as`), or its first three letters (`apis` → `api`). A slug the row's characters cannot hold is left empty.
- **Reserved words** — rows whose scope is `global` (names that become endpoints) get the Azure reserved-word check, like the existing storage account, key vault and SQL server rules.
- **Reviewed by hand** — the held rows were read again in the table and the pages it links. Rows with a complete rule were added by hand in `src/core/rules/azure-manual.ts` with the table text quoted; the reason of the others starts with "reviewed by hand".
