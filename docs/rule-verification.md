# Rule verification against official documentation

This document records how each naming rule in `src/core/constraints.ts` was checked against the cloud provider's official documentation: the 35 entries of `RULES` (24 checked on 2026-09-28, plus 11 added on 2026-10-06 — see "Rules added on 2026-10-06" below) and the 3 entries of `LABEL_LIMITS`. On 2026-09-28 each `docUrl` was fetched with `curl -sL`, the HTML tags were stripped, the relevant paragraph was located, and each anchor was confirmed against an `id` in the fetched HTML.

## How to read the tables

The four columns are ⑴ length, ⑵ allowed characters / pattern, ⑶ start / end, ⑷ reserved words / forbidden prefixes and suffixes.

| Verdict | Meaning |
|---|---|
| Match | The code value is the same as the document |
| Mismatch → fixed | The code differed from the document and was corrected. Recorded in [decisions.md](decisions.md) |
| Conservative | The code is stricter than the document. It may reject a valid name, but it never reports an invalid name as valid — kept as is and recorded in [decisions.md](decisions.md) |
| Not applicable | The document has no rule of that kind, and the code has none either |

Quotations here and in code comments copy the source word for word, typos included — for example the Compute Engine discovery document's `comply withRFC1035` (no space). Search for the source's spelling, not a corrected one.

**Summary** — rules without a documented source: **0** (no rule removed) · value fixes: **3** · `docUrl` fixes: **4** (plus anchor and domain cleanup) · conservative limits kept: **4**. On 2026-09-28 **3 more conservative limits were added** (GCS consecutive dots `..` forbidden · Azure resource group rejects characters above U+FFFF · Azure VM rejects all dots — rationale in [decisions.md](decisions.md)).

## Azure reserved words (added 2026-09-29)

Source: https://learn.microsoft.com/en-us/azure/azure-resource-manager/troubleshooting/error-reserved-resource-name — "Resources with an accessible endpoint, such as a fully qualified domain name, can't use reserved words or trademarks in the name." The naming rules page (`resource-name-rules`) also says: "Resources with a public endpoint can't include reserved words or trademarks in the name." The ⑷ verdicts in the RULES table above were made before this document was consulted; for the rules listed below, this section supersedes ⑷.

| Document | Code (`AZURE_RESERVED`) |
|---|---|
| ACCESS … XBOX, 38 entries — forbidden as words | `forbidden.words` — treated as a word when the characters before and after are not ASCII letters (digit, symbol, or end of name). **Conservative** — the document does not define "word" |
| MICROSOFT · WINDOWS — forbidden both as a word and as a substring | `forbidden.contains` |
| LOGIN — forbidden only at the start | `forbidden.prefixes` |
| The list is in uppercase | `forbidden.ignoreCase` — case-insensitive |

| Rules | Applied | Reason |
|---|---|---|
| `azure.storage_account` · `azure.key_vault` · `azure.sql_server` | Yes | They have a public FQDN (`*.core.windows.net` · `*.vault.azure.net` · `*.database.windows.net`) |
| `azure.virtual_machine` · `azure.virtual_machine_windows` · `azure.aks_nodepool_linux` · `azure.aks_nodepool_windows` | Yes (**Conservative**) | The resource itself has no public endpoint, but the name is used as a host name, so the case is ambiguous |
| `azure.resource_group` · `azure.managed_identity` · `azure.virtual_network` · `azure.subnet` | No | Logical resources whose names do not become DNS names |

On the same day the scope was aligned with the document table — `azure.subnet` is scoped to `virtual_network`, and AKS node pools to `managed_cluster` (`resource-name-rules`: "virtualnetworks / subnets | virtual network" · "managedClusters / agentPools | managed cluster"). Rationale in [decisions.md](decisions.md).
