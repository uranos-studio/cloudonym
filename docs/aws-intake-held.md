# AWS rules not imported yet

Source: [CloudFormation resource schemas](https://schema.cloudformation.us-east-1.amazonaws.com/CloudformationSchema.zip) (no version marker; the hash of the fields used is in `docs/rule-sources.lock.json`). Generated by `scripts/rules/build-aws-rules.mjs` — do not edit by hand.

Imported: **116** rules — 23 physical names and 93 Name tags (plus the types covered by hand-written rules, including those added by hand). Held: **39** types, listed below with the reason.

## How the imported rows were mapped

- **Scope** — the 18 namespaces are EC2, Lambda, ECR, ECS, EKS, RDS, DynamoDB, ElastiCache, Elastic Load Balancing (v1 and v2), API Gateway (v1 and v2), IAM, KMS, Secrets Manager, S3, EFS and CloudWatch Logs. Each type was classified by hand as having a name property (physical name), only a `Name` tag, no name, or an external value (DNS names).
- **Physical names** — imported only when the schema gives both a `pattern` and a `maxLength` for the name property. The pattern is kept verbatim and matched against the whole name (`^(?:…)$`; JSON Schema patterns are unanchored, the whole-name reading is narrower); `\Z` is read as end of input. The schema has no field for the uniqueness scope, so IAM names and Multi-Region Access Points are placed at account scope and the rest at Region scope, with a note that the scope is not confirmed. `docUrl` is the property anchor on the CloudFormation template reference page (checked on 2026-10-06).
- **Name tags** — EC2 types use the existing EC2 `Name` tag rule (any characters, 1–256). Other services use the general tag-value characters (letters, numbers, spaces and `_ . : / = + - @`, 1–256), because S3, IAM, RDS and others reject more characters than EC2. A type whose schema has a writable `VpcId` or `SubnetId` property is placed under the VPC node, otherwise under the Region (placement only — tags are not unique).
- **Prefix (slug)** — the initials of the type name when it has two or more words (`NatGateway` → `ng`), otherwise its first three letters. Same rule as the Azure fallback.
- **Reviewed by hand** — the held types were read again in each service's API reference (and the user guide or schema description where the API page is silent). Types with a complete rule were added by hand in `src/core/rules/aws-manual.ts` with the source sentence quoted; the reason of the others starts with "reviewed by hand".
